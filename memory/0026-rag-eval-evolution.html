  • 业界查证（2026-09-04）：产品框架（Ragas / DeepEval / TruLens）确以 precision / grounding 为主、无 citation recall/precision 实装指标；但研究侧 recall 成熟（ALCE EMNLP'23 / ALiiCE NAACL'25 / DeepTRACE ICLR'26 / OpenScholar Nature'26）——recall 的真正难点是 necessity（哪些句子必须引）与穷举；ALCE 默认全引、前提是"答案全由检索支撑"，与学习助手"内化作答合法"冲突，故 recall 不作产品红线。链接见阶段 C 末条。
  • 引用真实性两阶段落地的"隐藏细节"（2026-09-05 经验教训）：两阶段方法论只切开问题空间，不回答细节——阶段一需拆句粒度 / 改写保真（推断性语用成分不得删；实证：保真纪律保住"实际上"后，Run#122 #25 由 violation → ok）/ 编号纪律 / 硬上限；阶段二需锚点支撑 + 复合句覆盖 + 推断豁免 + reason 文案自洽 + 对子可审计。细节应沉淀为"引用判官实现核对清单"，避免换用例重踩。
  • 覆盖标注稳定性实证与"判官不稳先查上游"（2026-09-05 经验教训）：覆盖性检查（逐点核对回答是否覆盖）LLM 本身够用——点表修复后 16 点纯覆盖 ×100 = 1600/1600 零翻转；够用有两个前提：①判定任务纯净——一次调用只做一类认知任务（15 点 + transparency/format 叠加时 a5-c3 三次翻两次，摘掉附带任务后同一点稳定）；②点表粒度干净——o2-e2 的 7% 假阳性根因是点表把同一母题的概括（o2-c1）与细节（o2-e2 原版）拆成两个点、逼判官做粒度判别；a5-e3 的 3/20 翻转根因是探针只认"具体事故"而回答给的是"元教训"。判官不稳时第一反应不是加提示词规则或上确定性闸门，而是向上游查"这个判定任务本身是否被构造得可判定"；本次 prompt 探针、"禁止 evidence 与 v 自相矛盾"条款全部无效即为实证（LLM 不执行 if-then 约束）。
  • "能确定性的就确定性"修订为两条件启用原则（2026-09-05，沛东定）：确定性有隐性熵增成本——确定性手段看起来很美，但必然使整个系统趋向熵增，且熵增成本相当隐性；因此只在满足以下其一才考虑确定性手段：①实证证明用 LLM 无法实现足够可靠性，且充分分析确认不可靠来自 LLM 自身能力、不能靠拆解任务来破解；②LLM 手段的显性成本显著高于确定性手段（"显著"防的是被确定性表象诱惑）。配套认知：判官层先做任务拆解与金标准粒度修复（低代价、零熵增），确定性闸门从"必选项"降级为"可选兜底"。此原则由"要不要上确定性闸门"的犹豫逼出——prompt 探针失效后 Codex 推荐程序锚点闸门，沛东未立即采纳，坚持先用实验验证 LLM 在任务拆解后是否真不可靠，犹豫本身防止了过早引入确定性机制（详见现场细节阶段 C2）。
  • 输出结构须顺应生成方向：reason-first（2026-09-05，沛东归因，实验证实）：Transformer 逐 token 单向生成、无回改能力——自省只能前向体现在后续 token，无法回改已生成 token。凡"结论依赖依据"的输出，若结论先于依据生成，结论只是即时印象快照、依据才是延迟核对产物，两者必然可能脱节（实证：v-first 下 a5-c3 5/5 covered 的 evidence 全部写着 not_covered 的理由；同输出 evidence-first 后漂移 50% → 10%、矛盾消失；Run#125 a5-c3 20/20 not_covered）。设计原则：判官等"结论+依据"型输出一律 reason-first（先依据后结论，与 CoT 同构）；靠结构而非自觉保证一致性；程序一致性校验 / 确定性锚点仍作外部兜底。限定：此归因解释"结论与依据脱节"类问题；"核对错配"（把 A 点内容判给 B 点、跨源张冠李戴）是另一类，需探针排除锚 / 锚点闸门（见现场细节阶段 C3 #7 样本）。
  • 判官输入不是越少越好：任务纯净 ≠ 输入最小化（2026-09-05，反直觉实验结论）：覆盖标注"去证据块"对照实验（Run#125 #7 同输出 ×10）：有证据块 o2-e4 10/10 判对，去证据块后 6/10 把"模型资料局限元陈述"（"我掌握的两文均只有若干片段 / Claude Cowork 未展开细节"）误判为 OpenAI 文章"还在学什么"——错配 0% → 60%。机制：覆盖判官判断"输出是否覆盖点 X"隐含需区分"输出里的话是文章内容"还是"模型自己的元陈述 / 资料局限"，证据块是它唯一的原文参照系；砍掉参照只能凭字面联想。此前担心的"证据块稀释注意力致跨源错配"是低频事件（<10%，未复现），砍块引来的元陈述误判是高频错误。推论：职责分离（覆盖 / 引用 / format 各司其职）≠ 输入分离——覆盖判官不核对引用真实性，但仍需证据块作语义参照（详见现场细节阶段 C3）。
  • checklist 型金标准写作规范（2026-09-05 提炼，拟用于新用例作者 / 用例模板）：①点正交——两两检查：同一母题的概括与细节不拆成两个点；跨文语义相近类别（如两篇各自的"收尾/前瞻"小节）必须显式归属到源；②正面探针实例化——列出点名时必须出现的关键概念 / 术语或不可混淆的等价描述，让判官有词可查；③反例必备——明确"什么不算"：相邻点内容不算、背景 / 成效数字不算、模型元陈述（资料缺失 / 未覆盖全文 / 节选）不算文章内容；④跨源绑定 + 显式排除——多文档用例每点注明所属源，相似类别写"不是另一篇的 X"；⑤闭环——初稿 → 代表性输出稳定性 / 错配实验 → 把错配样本的反例补回 probe。定位：规范保证初稿结构合格、把踩坑从"随机分布"变成"结构已知的待补项"；反例完备性仍需实验迭代（详见现场细节阶段 C3 盲写验证）。
  • 判官不稳定分层处理与防过拟合（2026-09-05，沛东定）：系统性缺陷（探针没拦住判官主流误读，如 o2-e2 86% 假阳性）修到噪声级即可；残余错配（个位数百分比）若确认根源是机制性不可消除的判官噪声，不再单用例强压——每补一个反例都是"把本次跑批发现的失败形态填进金标准"，补到最后金标准成为历史输出样本的补丁集、对新输出形态欠拟合（"把未来知识填到过去，再验证发现该知识的用例"的循环）。残余噪声的正确处理 = repeat 统计吸收（多次跑、聚合 / 通过率），判官单次判定不稳定机制性不可消除（温度 0 亦然）。判别准则：先确认错判根源确属机制性噪声而非系统性缺陷，才停止强压（盲写版实证：86/24/20% → 4/0/2% 后收手）。

白盒归因机制定稿（2026-09-04 · 三件套第 3 件补全）

讨论收口（沛东"收"）：白盒层只服务根因归因、不每用例执行——检索充分性因此退化为"失败用例上的窄诊断"；需要查充分性的用例，其金标准必然已人写死要点清单（否则无本之木；诊断时让判官现拆要点会带回 Run#112 的不稳定）。

  • 来源锚：不补。动态定位 + 人审兜底更经济（每要点预标注工作量太大）；代价 = 金标准要点必须写得"可检索"（原子陈述、自含定位信息）。副作用：设计期"证据点分布分析"少了现成锚数据（属用例设计工具问题，不影响判官）。
  • 三态判别（口子②定稿）：分数不定边界，两级语义裁决，分数只当筛子与线索。先定义三个证据状态（针对"金标准里一个没答好的要点"）：
    — S1 注入已覆盖：本次注入给模型的证据里已有足以支撑该要点的材料 → 料够但答案没答好，锅在模型侧（没用上 / 用错 / 提炼错），不是检索的锅；
    — S2 库有未注入：注入集里没有支撑材料，但整个知识库里有（只是检索 / 注入环节没把它捞进来）→ 锅在检索 / 注入策略；
    — S3 库无：注入集和全库都找不到支撑材料 → 不是检索的锅，是语料缺口或金标准期望过高（如该要点本需跨段归纳，原材料里没有现成句）。
    判别流程：①来源级检查先行（确定性零成本）：要点绑定的点名来源是否进了注入（source_id）——没进直接落 S2；②注入集蕴含裁决（窄 LLM 判官，允许多块合证）：足以支撑 = S1；③不支撑才扩全库检索 + 同款蕴含裁决：全库有 = S2；没有 = S3（S3 内再分"语料真缺 / 要点需归纳、期望过高"，附全库最高分线索供人审）。防坑：允许"材料足够但需模型综合"（否则 harness 定义类归纳要点会被误判库无），禁止仅靠模型常识补全（防止 S2 串成 S1）。
  • 输出粒度（口子③定稿）：三布尔 + 首个卡点。检索充分性 过 / 不过 → 引用真实性 过 / 不过 → 提炼准确性 过 / 不过；附"首个卡点"（哪个要点、哪个状态、证据线索）给人审定因。充分性不过即短路、定案检索层，不展开后两段（存在性扫描：一个要点不充分就停）；与"一次只动一个变量"回归纪律一致（先修检索重跑，残留 fail 再归因下一层）；充分性不过但见凭空捏造引用时，输出只带"伪证标记"，不展开引用段。
  • 白盒引用真实性 = 红线（precision-only）+ 漏引，比黑盒严格；漏引挂充分性门后变简单。变简单三因：只查充分性过的用例；证据空间锁死注入集；与 faithfulness 共用同一归因引擎（有据未标 = 漏引 / 无据即幻觉）。残留难点："依托"不可观测——靠 trace（本次 run 是否真发生检索）收窄，纯内化未检索的 run 不触发漏引（内化直答合法、不罚沉默）；pass-run 的漏引不属白盒，归 faithfulness 抽样审计。

整体判断：检索充分性、引用红线、faithfulness 共用"声明 / 要点 × 证据块"归因原语；本组待办（14 条条款改写 / verdict-first 编排 / 提示词矩阵 / 白盒输出 schema）必须在原语与证据状态模型定稿后再动，落地仍先方案后实现。

  10. 引用红线管多宽？——rag-cmp-002 把判官逼到"recall vs precision"，业界查证落地（2026-09-04）

    这条"锋利版"对比题确实争气：从"三维度各自读清单互相矛盾"一路炸到"元陈述把整条 citation 红线挂起"，问题的形状终于清晰——沛东原话："我们这个用例还真不错，炸出了一堆不容易搞定的问题"。而这些问题其实在问同一件事：引用真实性这条红线，到底该管多宽？

    ① 沛东的方向判断：红线收敛到 precision 侧。"所有该标的都标了"是 recall 问题，要求穷举证明，不适合做产品红线；红线只需保证"答案中明确给出的引用必须来源真实、归属正确、内容与原文吻合"——给出即负责。能这样，红线就简单多了；没被找到的引用缺失不是红线问题，是召回 / 必要性审计问题。

    ② 元陈述的定位（延续上一轮辨析）：模型诚实声明"资料缺失 / 未收录 / 节选"（如"知识库中 Harness 一文明显缺整篇框架性段落"）属于证据侧不完整的可见症状（注入 12/43 块、A5 5/24、O2 7/19），不是回答侧"遗漏透明"义务的履行或违反，更不是引用伪证——不该由引用红线报告，否则就是"用引用尺子去强制发现检索不充分"，尺子必被做拧巴。

    ③ 白盒归因编排原则（沛东提出，Codex 认同；落地方式待拍板）：金标准是面向用户价值的黑盒判定；检索充分性、引用真实性是白盒诊断件。正确次序 = 先按金标准判 pass / fail / pending → 只有 fail / pending 才进入白盒归因，且按"检索充分性 → 引用真实性 → 提炼 / 总结"分层定位；白盒不必判得很准，但类必须分得清（检索不足 ≠ 引用错误 ≠ 提炼错误）。引用真实性因此不是每个用例每次执行都要跑的维度——判官重放里"citation 链在内容判定前先跑、把本可判定的 attempt 挂成 pending"，正是次序反了的症状。

    ④ 业界查证（2026-09-04；修正"主流工具只做 precision、citation recall 公认难做"的粗表述）：
    — 产品评测框架侧：确认主流确实以 precision / grounding 为主。Ragas 官方可用指标清单无 citation precision / recall / accuracy 实装页（citation_precision、citation_recall、citation_accuracy 三类 URL 直查均 404），其引用类考察 = 把回答 / 参考拆成声明、逐条判能否归因到检索上下文（faithfulness / context recall 式）；DeepEval 官方 RAG 指标 = Answer Relevancy / Faithfulness / Contextual Relevancy·Recall·Precision，无 citation 指标；TruLens 的 RAG Triad 中 groundedness = 把回答拆成声明、逐条在检索上下文找证据。注：网上有第三方课程演示 from deepeval.metrics import CitationRecall，但官方指标文档未收录，不能作为官方状态依据。
    — 研究侧：citation recall / precision 早已是成熟度量，"业界没人做 / 做不了 recall"不成立。ALCE（Gao et al., EMNLP 2023，Princeton）是首个 LLM 引用自动评测基准：citation recall = 每条 statement 至少带引用且 NLI 判定被引段落蕴含该句（没引用的句子 recall 即 0）；citation precision = 剔除对支撑无贡献的冗余引用。关键：ALCE 任务设定默认"几乎所有输出句都需要引用"，necessary 判定被绕开，前提是答案完全由检索支撑。ALiiCE（Xu et al., NAACL 2025 Main）把粒度压到句内：依赖树把句子拆成原子声明，算 positional citation recall / precision 与引用位置分布。DeepTRACE（Venkit et al., ICLR 2026）对 deep research 系统做声明级审计：citation accuracy（跨系统仅 40–80%）与 citation thoroughness（有没有引全）分成两个维度并列度量——thoroughness 单独成维，说明"该标的都标了"仍被当作与"标得对不对"并列的开放维度。OpenScholar / ScholarQABench（Asai et al., Nature 2026-02-04）：GPT-4o 在文献综述任务 78–90% 幻觉引用，OpenScholar 的 citation accuracy 追平人类专家——注意这里测的仍是"已给出的引用是否正确"（precision 侧），不是穷举 recall。
    — 修正后的准确表述：recall 方向（所有该标的都标了）的难点不是没有度量，而是 necessity 判定（哪些句子必须引）与穷举证明；ALCE 用"默认全引"回避 necessity。这个默认前提与我们的产品定位冲突——学习助手允许内化知识作答（0024 定稿：伪证红线条件触发、不罚沉默），不能套 ALCE"每句都必须有引用支撑"的设定。因此：红线收敛到 precision 侧（给出即负责）成立；引用缺失走 faithfulness / necessity 抽样审计（人工 / 低频），而非每次执行的自动化 fail。

  12. 白盒归因机制定稿：检索充分性"有得解吗"的完整讨论（2026-09-04，沛东"收"）

    Codex 判断：充分性不是证据集合的内在属性，而是"问题信息需求 × 证据"的关系——通用判官直接判"够不够"是病态问题；可解形态 = 三层拆解：①需求规格（要点清单 + 可选来源锚）；②点 → 证据定位（注入 → 全库两级，产出三态）；③归因输出。并指出：金标准列要点只完成规格的一半，还缺"逐点证据定位"；检索充分性、引用红线、faithfulness 的公共轴心是同一个"声明 / 要点 × 证据块"归因原语（业界同款：ALCE 的 citation recall = 被引段落 NLI 蕴含声明、遵循 AIS 框架）。
