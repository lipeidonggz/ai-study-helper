设计决策（用户已确认）

  • 进程内直连 loop：复用 run_agent_turn + Trace，不走 HTTP API——直接拿到完整 trace，无需 SSE 解析，不需要后端服务在跑
  • 自动判定范围：tool_used / tool_not_used / stream_complete / latency_budget 由机器判定；answer_correct / refusal 进 CSV 待人工标注列，不假装全自动
  • 并发默认 3 + --limit N 子集跑批
  • --llm fake 干跑模式：FakeLLM 验证管道，零成本
  • 人工标注 CSV 合并回报告 v1 不做（只出标注表，阶段 6 再系统化）
  • max_rounds 语义：指“预期最多调用几次工具”（工具执行次数），不是循环轮数——单次工具调用在 loop 里会经历 2 轮循环（决策轮 + 回答轮），用工具次数比较更直观

实现（backend/eval/runner.py）

  • run_case：组装输入（最后一条为当前消息、前面为历史，多轮就绪后生效）、asyncio.wait_for 超时控制、从 trace 提取工具调用/轮数/token/耗时
  • judge_case：自动判定 + pending_human 标记 + metrics（answer_contains / max_rounds / tool_calls_count）
  • run_all：信号量限流并发 + 汇总统计（状态分布、分类自动通过率、工具调用率、平均耗时、token 总量）
  • write_report：JSON 全量明细 + CSV 人工标注表（utf-8-sig，Excel 友好），写入 eval/reports/（已 gitignore）
  • CLI：python -m eval.runner --llm fake|real --limit N --concurrency M
  • builtin.clear_notes()：批次开始前重置笔记状态（进程级共享的隔离手段）

已知局限：笔记是进程级内存，并发跑批时 note 用例可能互相影响；需要严格隔离用 --concurrency 1（记录在 runner 文档与用例 notes 中）。
