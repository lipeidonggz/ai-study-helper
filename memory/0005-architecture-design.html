技术选型总览（已确认）

层面选型关键理由
架构形态前后端分离（逻辑边界，物理可同机部署）前端可替换，后端逻辑不动
前端Vue 3 + TypeScriptVue 2 已停止维护；组合式 API + TS 更顺
后端Python + FastAPIAgent 生态最强；异步/SSE 友好；Pydantic 承接工具 schema
流式输出SSE（非 WebSocket）单向服务器→客户端推送，基于 HTTP，自带重连
结构化存储SQLite嵌入式关系型，单文件零配置，单写多读，单用户足够
向量存储Qdrant（本地嵌入模式）元数据过滤强（知识库启停/优先级）、支持混合检索、本地→服务平滑演进
Embedding本地 BGE / sentence-transformers 类模型（v1 建议）本地化、免费、隐私好；DeepSeek API 无 embedding 端点
存储访问接口（Port）+ 实现（Adapter）换实现不换接口，为企业级扩展留位

横切关注点：

  • 范围控制：配置模型（全局 + 会话级）存于存储层，执行逻辑落在 Agent 核心（模式路由、兜底策略），展示在前端（引用、工具调用过程）。三处缺一不可。
  • 评测：独立于运行时，golden set + runner + 报告生成，阶段 1 起使用，阶段 6 系统化。

关键边界设计

  1. 流式进契约：Chat API 用 SSE，管理类用 REST；流式从第一天设计进 API。
  2. LLM 客户端统一接口：定义模型调用接口，兼容 DeepSeek/OpenAI 类 API，换模型/对照测试零改动上层。
  3. 工具执行器是安全边界：v1 本地进程执行 + 完整日志，阶段 4 沙箱化；边界先划好，后加防护不改结构。
  4. 编排器与组件解耦：Agent 核心内部区分编排器（loop 控制）与组件（工具、记忆、规划器），阶段 3/5 换编排器不重写整层。

存储抽象：接口（Port）+ 实现（Adapter）

原则：依赖倒置（业务只依赖接口）；按业务聚合划分接口，而非按表划分；v1 抽象目标是“换实现不换接口”，不模拟企业架构。

接口职责v1 实现企业级演进

技术注意点

  • 跨库一致性：文档元数据在 SQLite、向量在 Qdrant，非同一事务。v1 策略：SQLite 主写入 + 向量写入失败补偿回滚；企业级再演进 Outbox 等机制。
  • 接口粒度克制：DocumentStore 管元数据、VectorStore 管向量，检索时两者配合，不揉成巨型仓储。
  • SSE 断线恢复：v1 简单处理，完整断点恢复放到阶段 4。
