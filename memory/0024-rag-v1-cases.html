主体层 · RAG 用例设计方法论（读完即可用）

一句话主线：RAG 用例难在设计开放型回答的判定标准——通用 Agent 评测聚焦的"行为对错"（工具是否调用、拒答是否合理）升级为用户价值（黑盒）+ 工程诊断（白盒）两层判定；另因知识库既补"模型训练后的新知识"（知识更新延迟），也含"模型从未见过的私有内容"（如项目自有文档，非延迟问题）——而公开可得的素材会随时间被模型内化，用例体系必须内置时间维度（污染半衰期），防评测集随时间腐烂。

前置：产品定位与目标边界（这套口径为什么长这样）

产品定位：学习助手，不是"知识库问答机"。产品目标是帮助用户理解概念、解释原理、辅助学习，而不是把知识库内容原样捞出来。这个定位直接决定评测口径的三处形状：①允许内化直答——答得对就行，不强制"必须来自检索"，所以引用真实性只能是条件触发的红线，不能罚合法的内化作答；②表达合适性 = 教学形态匹配——问定义给定义、问对比给结构化对照、问"怎么学"给路径，形态本身是用户价值的一部分；③拒答按任务类型而非话题——学习/理解型问题正常回答，个人决策/行动执行型请求（如"给我具体操作方案"）才拒答并引导。

目标与边界（前篇 0023 的核心结论）：v1 只做 RAG 增强的单轮对话；知识库内容是"Agent 学习资料"（教程 / 业界文章 / 论文 / 项目自有笔记），服务的学习主线是"初步学到内化再到产出辅助"；判定以"用户价值（正确、合适、诚实）"为准绳，工程质量问题只做白盒记录。明确不做：多轮会话、复杂多跳检索——留到验证与迭代阶段，边界在这里先划清，评测口径才不会被"未来的功能"带偏。

2.0 整体步骤：从定位到可复用用例的五步

  1. 定产品定位与目标边界——判什么、允不允许内化、该拒什么，都由产品语义决定（见"前置"）；
  2. 定判定体系——用户价值层（g 门 + f 门内半权）+ 工程诊断层（引用红线 / 检索充分性 / faithfulness）的口径与公式；
  3. 出题——按"学习环节 × 用例类型"网格设计，逼检索 + 自然输入 + 按素材形态出题；先出题、不写实现；
  4. 金标准人工复核——AI 起草，人逐条过；写标准时就堵掉判官可能的偏置（三段式：判 pass 须同时满足 / 判 fail 任一即 fail）；
  5. 落地验证与迭代——补 schema 字段与素材 → 实现（入库/检索/判定）→ 真实跑批 → 逐条修复。本篇交付第 1-4 步成果与 12 条用例；第 5 步的验证与修复见后篇 0025。

2.1 核心结论与原因（为什么这样设计）

以下三条是最核心的设计结论，各附原因；推导全过程（含被推翻的草案）见考古层。

为什么判定要分"用户价值 + 工程诊断"两层？因为"评测什么"取决于用户能否直接观察、是否在意。用户看得到、在乎的（答案对不对、形态合不合适、该拒有没有拒）→ 进判分；用户看不见但坏了会影响质量的（引用的来源是否真实、检索是否够用、回答是否忠实于证据）→ 只做白盒记录，不掺进用户分数。一个反例能说明为什么要拆：若把"faithfulness（必须基于检索）"当判分维度，就会误杀"模型凭内化知识答对"的合法回答——学习助手允许内化直答，所以 faithfulness 只能当审计信号，不能当门槛。

为什么用例体系必须内置时间维度？因为公开素材会被模型训练内化：今天"必须靠检索才能答对"的题，一年后模型可能已经会了，用例悄悄失效（评测污染）。所以每条用例带 knowledge_date / decay_class / half_life 等字段，按腐烂速度分三类（永不 / 缓慢 / 快速）管理，到期进 review 而不是永远躺平。项目自有内容（模型绝不可能见过）是"永不腐烂"的干净素材，是逼检索最可靠的底牌。

为什么引用真实性是"条件触发"红线？红线只罚"依托检索或显式声称来源时的伪证"，不罚"凭内化知识作答"——因为后者合法（见上）。条件触发避免了两种误伤：模型没检索也没声称来源时不应被查；检索了但只是诚实直答也不应被罚。红线要抓的是三种伪证（来源不存在 / 内容与所引不符 / 归属错误）加引用缺失。

2.2 判定体系规范

总览（建议先读这段，再查表）：RAG 评测把"回答好不好"和"内部干得对不对"分开判——用户价值层只评两件事：行为正确性（g，作为门：该答的答对且切题、该拒答的正确拒答，错了就是 0）和表达合适性（f，只有在 g 通过后才按一半权重计分）；工程诊断层不判分，只当白盒看板：引用真实性是条件触发的红线（只有依托检索或显式声称来源才核对，伪证/归属错/引用缺失即 fail），检索充分性常驻记录、faithfulness 按需审计。用例按"结论会不会随模型内化而腐烂"分成三类管理（自有内容永不腐、经典内容缓慢腐、最新内容快速腐），所以每条用例都带时间与来源字段，到期进 review 而不是永远躺平。

2.3 用例设计方法

怎么出"能真正把问题逼出来的题"？四个动作：①逼检索——题要让模型"不检索就答不对"：细节题问原文表述 / 数字 / 案例，溯源题问出处与章节，对比题要求两源都覆盖，时效题问训练截止后内容，自有内容题问模型绝不可能知道的私有约定；②自然输入——用户 query 必须是真实用户会说的话，禁止用素材编号等内部代号（否则测的是"会不会用内部 API"而不是"会不会用产品"）；③金标准三段式——每条用例的金标准写成"判 pass（须同时满足：内容 / 表达 / 引用条件触发）+ 判 fail（任一即 fail）"，把判官可能的偏置（字面复述、口径冲突）在写标准时就堵掉；④按素材形态出题——题能不能答取决于素材以什么形态入库（清洗 / 切分 / 元数据），所以出题前先画"入库形态 × 模型熟悉度"矩阵（两个落地工具见本节后表：按学习环节的用例类型清单、出题可行性总图）。

12 条首轮用例怎么分布？O2《Harness engineering》4 条（定义 / AGENTS.md 地图 / 例子 / 判断题）+ A5《How we contain Claude》4 条（三组件 / 83% / 核心思路 / 93%）+ 项目自有 3 条（基础件规则 / 温度定档 / 统计方法）+ 跨文档对比 1 条（cmp-001）——覆盖 3 种素材形态与零/低模型熟悉度，把整条评测链路（检索 → 注入 → 生成 → 判定）跑通所需的最小用例集。

设计要点（2.3 细则）

  1. 四难点与对策：答案开放性 / 引用真实性新维度 / 模型太熟需逼检索 / 学习环节语义化——分别用要点覆盖评分、断言级核对、逼检索构造、判定难度排序解决；
  2. 逼检索五技巧：细节题（原文表述 / 数字 / 案例）、溯源题（出处 / 章节）、对比题（两个来源必须都检索到）、时效题（2025-2026 新内容）、自有内容题（模型绝对不知道）；

阶段 A · 判定体系设计（2026-09-01）

  1. 坑大的担忧（沛东）：0023 素材清单定稿后，沛东粗略想了下用例怎么搞，觉得"坑挖得有点大，不怎么好搞"。Codex 确认难是真实的，拆成四个难点：答案开放性 / 引用真实性新维度 / 模型太熟需逼检索 / 学习环节语义化。

  3. 【决策点】步骤确认（沛东拍板）：先做①判定维度 ②用例类型清单，给沛东过目；确认后进入逐条用例设计。进入新工作阶段，笔记换新文件 0024。
  4. 草案初稿（Codex 产出，沛东审阅的对象）：Codex 按"复用 0022 机制、加 RAG 维度"的思路产出初始判定维度 = 4 判分 + 1 诊断：引用真实性（红线级）、忠实度（回答须基于检索内容，不编造）、正确完整性（金标准关键点覆盖）、相关性（切题）+ 检索充分性（诊断，失败归因）。沛东就是对着这份草案发出下面的三连问。
  5. 三连质疑（沛东，草案被拆）：沛东连发三问，看似三个独立问题，实则指向同一个本质。①忠实度："知识库外零编造是啥意思？作为学习助手我们并不在意是否用知识库外内容，什么叫编造？"——用户视角 vs 系统视角的分野开始浮现；②三个用户诉求："正确解答所有问题 / 表达方式与问题匹配 / 没有答案明确说不知道"，并指出后两个诉求草案里没有对应；③"引用真实性像是打开内部看的二层判别指标？相关性跟正确完整性会重叠？检索充分性也是内部指标——我们要评测的是有 RAG 赋能的 Agent，需要把这些嵌进去吗？"
  6. 【决策点】为什么拆两层（核心推理，2026-09-01）：三问的共同本质是——"这套维度到底在评测什么？"答案是：我们要评测的是有 RAG 赋能的 Agent（用户可见的整体），不是 RAG 内部环节。由此产生两条用途不同的线：用户价值层——用户能否直接观察、是否在意这个表现？能且在意 → 进复合分（对外验收的尺子）；工程诊断层——用户看不见或不关心，但坏了会影响系统质量 → 不判分只记录（对内修理的仪表盘）。分层判据 = "用户能否直接观察 / 是否在意"。草案的毛病正是把两个世界混在一个列表里：忠实度（用户不观察，内部指标）被当成判分维度，会误伤"允许内化知识"的正常回答；相关性被正确完整性覆盖（答非所问即不正确）；引用真实性 / 检索充分性混进来又稀释了用户评分。分层不是维度数量的整理，是评测目的的分野：对外验收 vs 对内归因。
  7. 【决策点】修订结果（两层判定定稿）：忠实度概念纠偏为诚实性（把"是否用知识库"与"是否编造"分开，学习助手只关心后者）；新增表达合适性（对应 0023 应答形态轴）；相关性并入正确完整性；引用真实性 / 检索充分性降为工程诊断层。用户价值层 = 正确完整性 + 表达合适性 + 拒答校准（诚实性落地为业界术语）；工程诊断层 = 引用真实性（红线）+ 检索充分性（常驻）。
  8. 【决策点】业界查证（2026-09-01）：Ragas / DeepEval / FutureAGI / Thoughtworks 一致采用三层评测——Retrieval 层（context precision / recall、MRR、NDCG）+ Generation 层（faithfulness、citation quality、answer relevance、context utilization）+ End-to-end 层（answer correctness、helpfulness、refusal calibration、format compliance）。映射确认：我们的用户价值层 = 业界 End-to-end 层（三个用户诉求在业界都有标准名：answer correctness / format compliance / refusal calibration，且拒答校准明确属 End-to-end 层）；工程诊断层 = Retrieval + Generation 层。唯一刻意偏离：业界 faithfulness 定义"只允许基于检索内容"，对知识库问答工具成立，但我们定位允许内化知识，所以 faithfulness 不进用户判分。
  9. 【决策点】faithfulness 定位（沛东追问）：沛东问"faithfulness 加进诊断指标了吗？应该是吗"。Codex 定调：faithfulness 是评测可信度审计工具，不是产品运行诊断——因为"回答没完全基于检索"对学习助手不是错误（允许内化知识），但它低 + 答案正确 = "模型不靠检索也答对"的评测污染最强信号（正好对应 0022 评测可信度主线）。落地：不常驻每次 attempt，跑批后对"答案正确"的用例抽样审计，比例升高说明用例失效需换题。与检索充分性（常驻，产品归因）分工：一个回答"这次失败在哪"，一个回答"这次答对是否靠检索"。
  10. 【决策点】污染半衰期洞察（沛东，2026-09-01）：沛东指出——按产品定位 + 知识库内容定位，RAG 不只是弥补大模型知识更新延迟（除公开素材外，项目自有内容属"模型从未见过"的私有知识，与延迟无关），所以"现在靠检索才能答对的问题，一年后可能已被模型内化"，评测用例必须随时间更新。Codex 查证业界：ACL 2026《Test of Time》研究 post-cutoff performance decay 作为污染信号；FreshQA 动态基准持续刷新对抗知识内化；ACM MM 2026 发现动态评测仍残留 17%-29% 污染（新题也可能用旧知识验证）。结论：用例按污染半衰期分三类（永不退化：自有内容 + 行为契约；缓慢退化：经典内容；快速退化：最新知识），逼检索强度与半衰期挂钩；faithfulness 审计兼任污染检测器；素材源（The Batch / arXiv）持续更新供给新鲜用例；用例 schema 加时间字段。沛东确认成立。

  5. 【决策点】引用真实性判定口径（2026-09-01，沛东拍板 A 严格版）：沛东问引用真实性在用例中如何体现。Codex 给出三层面落点：①用例层——criteria 挂 citation_truth、source_ref 锚定应引用的素材、金标准写明引用 pass/fail；②判定层——断言级两阶段（拆断言 → 逐条对照检索片段与素材元数据核对存在性/吻合性/归属，任一条违规即红线 fail）；③边界待拍板：回答没引用来源怎么判。沛东拍板 A（严格）：RAG 关键事实必须带来源，无来源 = 引用缺失 = fail；通用知识回答走「通用知识 + 标注」策略，不归引用真实性管；声称来自知识库却对不上 = 红线。配套：12 条金标准批量修订——每条补「表达合适性」（criteria + 金标准应答形态要求）与引用口径，判 pass/fail 统一为内容 / 表达 / 引用三部分。注意：本口径的触发条件随后被沛东洞察细化，见下条。
  6. 【决策点】引用真实性触发条件细化（2026-09-01，沛东洞察）：沛东指出——模型可能已在训练中内化素材内容（如 A5），未调用工具/未触发检索就答对；按产品定位（通用知识回答合法）与污染半衰期原则（内化 = 用例退化信号而非错误答案），此时强制要求引用会错杀正确回答。Codex 确认并修订：引用真实性是伪证红线，条件触发——仅在「回答论断依托检索内容（faithfulness 高）或显式声称来源」时生效，须来源真实存在、归属正确、内容与原文吻合；凭内化知识作答且未声称来源 → 不触发、不判 fail，由 faithfulness 审计记污染信号（评测可信度层处理）。三种伪证形态：①来源不存在（伪造）；②内容与所引来源原文不符（曲解/嫁接）；③归属错误（张冠李戴）。另定义：依托检索内容作答却未标注来源 = 引用缺失 = fail。实现联动：判官需拿到「检索是否触发 + 注入的检索片段」（类似现有 tool_execs 传递），faithfulness 决定是否依托检索、引用真实性决定依托了必须说真话。12 条金标准引用条款统一改为条件式。
  7. 【决策点】金标准模板修订（2026-09-01，沛东审阅驱动）：沛东逐条复核发现两个判官偏置风险：①「含义 = 完整句」写法会诱导判官精确复述而非语义匹配（机制层判官提示词已有反字面匹配指令，但措辞偏置防不胜防）→ 判据式等号改要点式并显式声明「表述不限，意思一致即可」，定义式等号（概念名→含义）保留；②判 pass/fail 的逻辑是隐含的（pass=三条 AND、fail=任一 OR），判官可能误读 → 模板显式化：「判 pass：以下三条须同时满足」「判 fail：满足以下任一情形即 fail」。12 条金标准统一修订并验证；AND/OR 约定将在 RAG 判官提示词实现时内置一次，金标准每条仍显式书写（双保险）。补充（2026-09-02）：沛东复核 a5-003 发现解释类内容仍易被绝对化理解（其余 11 条同病）→ 判 pass 开头统一加「内容与解释以意思一致为准、表述不限；精确数字/名称/出处须准确」，12 条全部生效。
  8. 【决策点】用例输入必须自然化（2026-09-01，沛东审阅发现）：沛东发现 rag-a5-002 用户 query 写「A5 文中」——A5 是 manifest 内部编号，真实用户不可能知道。Codex 扫描 12 条输入，共 4 处内部编号/不自然说法：a5-002/a5-004 的「A5」→ 改为「Anthropic《How we contain Claude》」；own-002/own-003 的「0022」→ 改为自然说法（「之前做主动调校时」「咱们评测体系的加权复合分」）——后者顺带把「按笔记号查」变成「靠内容检索到笔记」，检索测试更真实。经验沉淀：用例输入一律用真实用户的自然表达，不得使用 manifest 编号/内部代号；引用锚定靠 source_ref 与金标准，不靠用户提问里点名。
  9. 【决策点】12 条用例人工复核定稿（2026-09-02）：沛东逐条复核全部 12 条用例，手动微调 3 处 fail 条款（rag-o2-004 补"结论对但理由错"情形；rag-own-001/002 分号改"或"）；Codex 统一补"内容与解释以意思一致为准、表述不限"全局约束；金标准最终定稿并提交（commit 54b41f9）。
  10. 【决策点】层级判定模型（2026-09-02，沛东洞察）：沛东指出三个用户价值维度不是并行权重关系，而是门控层级——正确完整性错了，表达合适性不应得分；拒答校准也不是独立维度。Codex 形式化为两阶段模型：阶段 1 行为正确性 g 为门（应回答→正确完整性含切题、过度拒答=0；应拒答→是否正确拒答、未拒/编造=0）；阶段 2 表达合适性 f 仅在 g 大于 0 时计分；拒答校准溶解进 g（拒答不足 / 过度拒答 / 编造均映射为 g=0）。沛东拍板合成公式 B：attempt = g × (0.5 + 0.5×f)。落地约定（实现阶段）：schema 加 expected_mode（answer / refuse，默认 answer）、判官输出 g / f / 引用 verdict / 诊断信号、金标准标注预期模式。原"维度权重=等权"表述被此模型取代。

  • 引用真实性（citation_truth，红线级）：回答中引用的来源必须真实存在于知识库且内容吻合；伪造 / 张冠李戴 / 编造来源 = fail。对应 v1.0 引用真实性硬约束。
  • 忠实度（faithfulness，判分）：回答内容是否基于检索到的知识库片段；不得编造知识库没有的事实 / 数字 / 表述。对应"知识库外零编造"。
  • 正确完整性（answer_correct，判分）：答案是否正确、是否覆盖金标准关键点；开放型回答按要点覆盖打分（部分分）。
  • 相关性（relevance，判分）：回答是否切题、没有答非所问；检索到无关内容但强行回答 = 扣分。
  • 检索充分性（retrieval_sufficiency，诊断）：记录"是否检索到足以回答的内容"与"回答是否用上了检索内容"，不直接判 pass/fail，用于失败归因（没检索到 vs 检索到没用上）。

拆解过程概要：忠实度把"是否用知识库"与"是否编造"混为一谈（学习助手只在意后者，概念纠偏为诚实性）；相关性被正确完整性覆盖；引用真实性 / 检索充分性属"打开内部看"的二层指标，降为工程诊断层；另补用户真实诉求"表达合适性"与"拒答校准"。详见下方定稿版。

判定维度（定稿，两层）：

  • 用户价值层（黑盒，判分，进复合分）：
    • 正确完整性（answer_correct）：答案正确、覆盖金标准关键点，开放型按要点覆盖给部分分；含切题（相关性并入：答非所问即不正确）。
    • 表达合适性（format_appropriateness）：应答形态与问题类型匹配——问"是什么"给定义、问"区别"给对比、问"怎么开始"给路径、问"总结"给要点、问"出题"给题目；答对但形态错位（如问定义却给整章概述）= 扣分。
    • 拒答校准（refusal_calibration）：知识库与模型都不知道时明确说不知道；不编造事实 / 数字 / 来源；过度拒答是 UX 问题，拒答不足是安全问题（业界定义）。
  • 工程诊断层（白盒，不判分）：
    • 引用真实性（citation_truth，红线级）：引用的来源必须真实存在于知识库且内容吻合；伪造 / 张冠李戴 / 编造来源 = fail（must_pass 闸门，不进复合分）。对应 v1.0 引用真实性硬约束。
    • 检索充分性（retrieval_sufficiency，常驻诊断）：记录"是否检索到足以回答的内容"与"回答是否用上了检索内容"，失败归因（没检索到 vs 检索到没用上）。
    • faithfulness（按需审计）：回答论断与检索内容的吻合度；评测可信度审计——低 + 答案正确 = 用例被模型内化（评测污染），提示换题；不常驻打分。

注（2026-09-02）：用户价值层原三个维度（正确完整性 / 表达合适性 / 拒答校准）已重组为两个判定要素（行为正确性 g + 表达合适性 f）——正确完整性与拒答校准合并为"行为正确性 g"（按金标准预期模式取不同形态：应回答→正确完整性含切题、过度拒答=0；应拒答→是否正确拒答、未拒/编造=0）；表达合适性 f 仅在 g 大于 0 时计分；attempt = g × (0.5 + 0.5×f)。下方"定稿，两层"按并行维度记录，供对照理解，判定时以层级模型为准。
