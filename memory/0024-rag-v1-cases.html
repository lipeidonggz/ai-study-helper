第一部分 · 思路简要描述 + 结论（复习先读这里）

一句话主线：RAG 用例难在设计开放型回答的判定标准——阶段 1 的"行为对错"升级为用户价值（黑盒）+ 工程诊断（白盒）两层判定；另因知识库本质是"弥补模型知识更新延迟"，用例体系必须内置时间维度（污染半衰期），防评测集随时间腐烂。

结论清单

  1. 难度定性：RAG 用例的难是真实的，拆成四个性质不同的难点——①答案开放性（生成式回答无确定对错）②引用真实性是新判定维度（需对照原文片段）③模型太熟需"逼检索"（细节/出处/新内容类题目）④学习环节语义化（把"解惑/辨析/梳理"转成可判定用例）。四个难点分别有成熟解法或构造技巧，不是不可解。
  2. 判定维度（定稿，两层）：分层判据 = "用户能否直接观察 / 是否在意"——评测对象是"有 RAG 赋能的 Agent"整体，不是 RAG 内部环节。用户价值层（黑盒，判分）= 正确完整性（含切题，答非所问即不正确）+ 表达合适性（应答形态与问题类型匹配）+ 拒答校准（知识库与模型都不知道时明确说不知道、不编造；过度拒答是 UX 问题，拒答不足是安全问题）；工程诊断层（白盒，不判分）= 引用真实性（红线级：伪造来源直接 fail，不进复合分）+ 检索充分性（常驻诊断：失败归因）+ faithfulness（按需审计：评测可信度）。两层分别服务对外验收（用户价值）与对内归因（工程诊断），混在一个列表里会互相污染。
  3. 污染半衰期原则（沛东洞察，2026-09-01）：知识库本质是"模型不知道什么"——除项目自有内容外，绝大部分素材公开可得，模型会随时间内化，导致"现在靠检索才能答对、一年后模型直接会"；用例因此按污染半衰期分四类（自有内容 / 行为契约：永不退化；经典内容：缓慢退化；最新知识：快速退化），逼检索强度与半衰期挂钩，并用 faithfulness 审计作为"用例污染检测器"，素材源（The Batch / arXiv）持续更新供给新鲜用例。业界对应：FreshQA 动态基准、ACL 2026 post-cutoff decay 研究——动态评测只能降低不能消除污染（新题仍残留 17%-29% 可被旧知识验证）。
  4. 用例类型清单（草案，按学习过程主线组织）：九个环节 × 若干题型，先做判定容易的（溯源求证 / 细节问答 / 引用核查——有原文可依，金标准好写），再做开放型（梳理 / 辨析——要点覆盖标准）。每个环节先 3-5 条，跑通评测链路再扩。
  5. 逼检索构造技巧（针对模型熟悉度）：细节题（问原文具体表述 / 数字 / 案例）、溯源题（问观点出自哪篇 / 哪个章节）、对比题（问两个来源异同，必须都检索到）、时效题（2025-2026 新内容）、自有内容题（问项目文档细节，模型绝对不知道）。
  6. 流程：判定维度（接口层）→ 用例类型清单（骨架，taxonomy-first）→ 逐条对着素材出题（内容驱动填用例）→ 人工逐条审金标准（沿用 0022 原则，AI 起草、人工复核）。

第二部分 · 现场细节（复原现场用）

讨论历程（决策链）

  1. 坑大的担忧（沛东）：0023 素材清单定稿后，沛东粗略想了下用例怎么搞，觉得"坑挖得有点大，不怎么好搞"。Codex 确认难是真实的，拆成四个难点：答案开放性 / 引用真实性新维度 / 模型太熟需逼检索 / 学习环节语义化。
  2. 解法对照：①忠实度 / 相关性 / 上下文相关性是 RAG 评测业界成熟维度，项目已有加权复合分 + 连续打分基础，只加维度不改机制；②引用核查 = "断言 + 出处"逐条对，判官从"对照工具事实"扩展为"对照检索片段"；③逼检索技巧 = 细节 / 出处 / 新内容题，正对应选材时"模型熟悉度低"素材的用途；④学习环节语义化最需自己设计，用"判定难度排序"绕开——先做有原文可依的题型。
  3. 步骤确认（沛东拍板）：先做①判定维度 ②用例类型清单，给沛东过目；确认后进入逐条用例设计。进入新工作阶段，笔记换新文件 0024。
  4. 草案初稿（Codex 产出，沛东审阅的对象）：Codex 按"复用 0022 机制、加 RAG 维度"的思路产出初始判定维度 = 4 判分 + 1 诊断：引用真实性（红线级）、忠实度（回答须基于检索内容，不编造）、正确完整性（金标准关键点覆盖）、相关性（切题）+ 检索充分性（诊断，失败归因）。沛东就是对着这份草案发出下面的三连问。
  5. 三连质疑（沛东，草案被拆）：沛东连发三问，看似三个独立问题，实则指向同一个本质。①忠实度："知识库外零编造是啥意思？作为学习助手我们并不在意是否用知识库外内容，什么叫编造？"——用户视角 vs 系统视角的分野开始浮现；②三个用户诉求："正确解答所有问题 / 表达方式与问题匹配 / 没有答案明确说不知道"，并指出后两个诉求草案里没有对应；③"引用真实性像是打开内部看的二层判别指标？相关性跟正确完整性会重叠？检索充分性也是内部指标——我们要评测的是有 RAG 赋能的 Agent，需要把这些嵌进去吗？"
  6. 为什么拆两层（核心推理，2026-09-01）：三问的共同本质是——"这套维度到底在评测什么？"答案是：我们要评测的是有 RAG 赋能的 Agent（用户可见的整体），不是 RAG 内部环节。由此产生两条用途不同的线：用户价值层——用户能否直接观察、是否在意这个表现？能且在意 → 进复合分（对外验收的尺子）；工程诊断层——用户看不见或不关心，但坏了会影响系统质量 → 不判分只记录（对内修理的仪表盘）。分层判据 = "用户能否直接观察 / 是否在意"。草案的毛病正是把两个世界混在一个列表里：忠实度（用户不观察，内部指标）被当成判分维度，会误伤"允许内化知识"的正常回答；相关性被正确完整性覆盖（答非所问即不正确）；引用真实性 / 检索充分性混进来又稀释了用户评分。分层不是维度数量的整理，是评测目的的分野：对外验收 vs 对内归因。
  7. 修订结果（两层判定定稿）：忠实度概念纠偏为诚实性（把"是否用知识库"与"是否编造"分开，学习助手只关心后者）；新增表达合适性（对应 0023 应答形态轴）；相关性并入正确完整性；引用真实性 / 检索充分性降为工程诊断层。用户价值层 = 正确完整性 + 表达合适性 + 拒答校准（诚实性落地为业界术语）；工程诊断层 = 引用真实性（红线）+ 检索充分性（常驻）。
  8. 业界查证（2026-09-01）：Ragas / DeepEval / FutureAGI / Thoughtworks 一致采用三层评测——Retrieval 层（context precision / recall、MRR、NDCG）+ Generation 层（faithfulness、citation quality、answer relevance、context utilization）+ End-to-end 层（answer correctness、helpfulness、refusal calibration、format compliance）。映射确认：我们的用户价值层 = 业界 End-to-end 层（三个用户诉求在业界都有标准名：answer correctness / format compliance / refusal calibration，且拒答校准明确属 End-to-end 层）；工程诊断层 = Retrieval + Generation 层。唯一刻意偏离：业界 faithfulness 定义"只允许基于检索内容"，对知识库问答工具成立，但我们定位允许内化知识，所以 faithfulness 不进用户判分。
  9. faithfulness 定位（沛东追问）：沛东问"faithfulness 加进诊断指标了吗？应该是吗"。Codex 定调：faithfulness 是评测可信度审计工具，不是产品运行诊断——因为"回答没完全基于检索"对学习助手不是错误（允许内化知识），但它低 + 答案正确 = "模型不靠检索也答对"的评测污染最强信号（正好对应 0022 评测可信度主线）。落地：不常驻每次 attempt，跑批后对"答案正确"的用例抽样审计，比例升高说明用例失效需换题。与检索充分性（常驻，产品归因）分工：一个回答"这次失败在哪"，一个回答"这次答对是否靠检索"。
  10. 污染半衰期洞察（沛东，2026-09-01）：沛东指出——按产品定位 + 知识库内容定位，RAG 只是在弥补大模型知识更新延迟（除项目自有内容外大部分公开可得），所以"现在靠检索才能答对的问题，一年后可能已被模型内化"，评测用例必须随时间更新。Codex 查证业界：ACL 2026《Test of Time》研究 post-cutoff performance decay 作为污染信号；FreshQA 动态基准持续刷新对抗知识内化；ACM MM 2026 发现动态评测仍残留 17%-29% 污染（新题也可能用旧知识验证）。结论：用例按污染半衰期分四类（自有内容 / 行为契约：永不退化；经典内容：缓慢退化；最新知识：快速退化），逼检索强度与半衰期挂钩；faithfulness 审计兼任污染检测器；素材源（The Batch / arXiv）持续更新供给新鲜用例；用例 schema 加时间字段。沛东确认成立。
  11. 草案确认与权重（沛东拍板，2026-09-01）：沛东确认 0024 草案三件套——判定维度两层定稿、污染半衰期原则、用例类型清单十题型；拍板各维度等权（拒答校准未单独拍板设闸门，默认沿用 0022 用例级 must_pass 红线机制）。随后拍板素材策略：按 0023 已定范围全部采集（教程 / 文章 / The Batch / 国内厂商；论文走半自动入库 UI）。
  12. 引用真实性粒度讨论（2026-09-01，沛东关注成本）：两种方案优劣——断言级：错误归因清晰（能定位到具体哪句编造）、可部分得分、与 v1.0"逐条可溯源"硬约束语义一致；代价是判定成本更高。回答级：一次判定省 token、与用户感知一致；但粒度粗、归因弱、易漏判单句编造（整体看起来对但某句张冠李戴）。Codex 指出成本不是"1 vs N 次"：断言级可用单次调用 + 结构化多断言输出实现，成本约为回答级 1.5-2.5 倍而非 N 倍；还可做"回答级预筛 + 命中风险才断言级深查"两级方案。业界 citation 评测普遍按断言/逐条核对（Ragas citation precision/recall）。结论（2026-09-01 定）：沛东拍板断言级；Codex 进一步查证业界实现——DeepEval / Ragas 均为两阶段各单次调用（拆原子声明 1 次 + 批量核对 1 次，结构化输出），不是逐断言 N 次调用；Ragas 还可用本地 NLI 模型（HHEM）替代 LLM 核对以省 API 成本；逐条调用仅见于小众工具（citation-audit-kit）。最终决策：断言级 + 两阶段各单次调用；"回答级预筛"两级方案留作成本敏感时的后置优化（沛东："真贵了再改"）。
  13. 用例 schema 时间字段设计（2026-09-01，沛东确认）：Codex 提出九字段草案，核心设计：①字段服务"用例生命周期"而非纯记录——到期仅进 review 队列、不自动改判，人工或 faithfulness 审计决定换题 / 降级 / 退役；②half_life 是动态校准的先验值——faithfulness 审计发现"低 faith + 答对"（模型已内化）提前触发 review、写回 pollution_flags，同类用例先验可调短；③三类默认参数——never（自有内容 / 行为契约）：∞ / 仅随内容变更重审；slow（经典内容）：365 / 年度，靠出处溯源题逼检索；fast（最新知识）：90 / 季度，细节题 + 素材持续更新供给新题；④兼容 0022：时间字段全部可选。沛东确认，并补充拍板：存量用例默认按 never 处理（存量以行为契约 / 自有内容为主，不随时间退化）。
  14. 出题可行性总图（2026-09-01，沛东洞察）：沛东指出——出题无法与入库端处理解耦，题能不能答取决于素材以什么形态入库（清洗 / 切分 / 元数据 / 向量化），不能只看模型熟悉度一个维度。Codex 据此画出总图 = 入库形态 × 模型熟悉度矩阵（7 形态 × 4 档熟悉度），每格给代表素材、可出题型与技术前提；技术耦合点：HTML 正文提取（JS 渲染页有坑）/ 结构化数据是纯向量弱项 / 跨文档对照依赖元数据 / 自有文档需 HTML 清洗。首轮切片：①HTML 网页 × 低（O2+A5：细节/溯源/辨析）②自有文档 × 零（0022/AGENTS.md：细节/溯源）③多文档 × 低（harness 三方对照：批判认知）——覆盖 3 种入库形态、零/低熟悉度，把整条评测链路跑通。沛东确认总图，并明确：先出题、暂不实现 Agent 代码。
  15. 引用真实性判定口径（2026-09-01，沛东拍板 A 严格版）：沛东问引用真实性在用例中如何体现。Codex 给出三层面落点：①用例层——criteria 挂 citation_truth、source_ref 锚定应引用的素材、金标准写明引用 pass/fail；②判定层——断言级两阶段（拆断言 → 逐条对照检索片段与素材元数据核对存在性/吻合性/归属，任一条违规即红线 fail）；③边界待拍板：回答没引用来源怎么判。沛东拍板 A（严格）：RAG 关键事实必须带来源，无来源 = 引用缺失 = fail；通用知识回答走「通用知识 + 标注」策略，不归引用真实性管；声称来自知识库却对不上 = 红线。配套：12 条金标准批量修订——每条补「表达合适性」（criteria + 金标准应答形态要求）与引用口径，判 pass/fail 统一为内容 / 表达 / 引用三部分。注意：本口径的触发条件随后被沛东洞察细化，见下条。
  16. 引用真实性触发条件细化（2026-09-01，沛东洞察）：沛东指出——模型可能已在训练中内化素材内容（如 A5），未调用工具/未触发检索就答对；按产品定位（通用知识回答合法）与污染半衰期原则（内化 = 用例退化信号而非错误答案），此时强制要求引用会错杀正确回答。Codex 确认并修订：引用真实性是伪证红线，条件触发——仅在「回答论断依托检索内容（faithfulness 高）或显式声称来源」时生效，须来源真实存在、归属正确、内容与原文吻合；凭内化知识作答且未声称来源 → 不触发、不判 fail，由 faithfulness 审计记污染信号（评测可信度层处理）。三种伪证形态：①来源不存在（伪造）；②内容与所引来源原文不符（曲解/嫁接）；③归属错误（张冠李戴）。另定义：依托检索内容作答却未标注来源 = 引用缺失 = fail。实现联动：判官需拿到「检索是否触发 + 注入的检索片段」（类似现有 tool_execs 传递），faithfulness 决定是否依托检索、引用真实性决定依托了必须说真话。12 条金标准引用条款统一改为条件式。
  17. 金标准模板修订（2026-09-01，沛东审阅驱动）：沛东逐条复核发现两个判官偏置风险：①「含义 = 完整句」写法会诱导判官精确复述而非语义匹配（机制层判官提示词已有反字面匹配指令，但措辞偏置防不胜防）→ 判据式等号改要点式并显式声明「表述不限，意思一致即可」，定义式等号（概念名→含义）保留；②判 pass/fail 的逻辑是隐含的（pass=三条 AND、fail=任一 OR），判官可能误读 → 模板显式化：「判 pass：以下三条须同时满足」「判 fail：满足以下任一情形即 fail」。12 条金标准统一修订并验证；AND/OR 约定将在 RAG 判官提示词实现时内置一次，金标准每条仍显式书写（双保险）。补充（2026-09-02）：沛东复核 a5-003 发现解释类内容仍易被绝对化理解（其余 11 条同病）→ 判 pass 开头统一加「内容与解释以意思一致为准、表述不限；精确数字/名称/出处须准确」，12 条全部生效。
  18. 用例输入必须自然化（2026-09-01，沛东审阅发现）：沛东发现 rag-a5-002 用户 query 写「A5 文中」——A5 是 manifest 内部编号，真实用户不可能知道。Codex 扫描 12 条输入，共 4 处内部编号/不自然说法：a5-002/a5-004 的「A5」→ 改为「Anthropic《How we contain Claude》」；own-002/own-003 的「0022」→ 改为自然说法（「之前做主动调校时」「咱们评测体系的加权复合分」）——后者顺带把「按笔记号查」变成「靠内容检索到笔记」，检索测试更真实。经验沉淀：用例输入一律用真实用户的自然表达，不得使用 manifest 编号/内部代号；引用锚定靠 source_ref 与金标准，不靠用户提问里点名。

草案记录

草案初稿（4 判分 + 1 诊断，被沛东三连问拆解，仅存档）：Codex 按"复用 0022 机制、加 RAG 维度"思路产出，是沛东审阅的第一版——

  • 引用真实性（citation_truth，红线级）：回答中引用的来源必须真实存在于知识库且内容吻合；伪造 / 张冠李戴 / 编造来源 = fail。对应 v1.0 引用真实性硬约束。
  • 忠实度（faithfulness，判分）：回答内容是否基于检索到的知识库片段；不得编造知识库没有的事实 / 数字 / 表述。对应"知识库外零编造"。
  • 正确完整性（answer_correct，判分）：答案是否正确、是否覆盖金标准关键点；开放型回答按要点覆盖打分（部分分）。
  • 相关性（relevance，判分）：回答是否切题、没有答非所问；检索到无关内容但强行回答 = 扣分。
  • 检索充分性（retrieval_sufficiency，诊断）：记录"是否检索到足以回答的内容"与"回答是否用上了检索内容"，不直接判 pass/fail，用于失败归因（没检索到 vs 检索到没用上）。

拆解过程概要：忠实度把"是否用知识库"与"是否编造"混为一谈（学习助手只在意后者，概念纠偏为诚实性）；相关性被正确完整性覆盖；引用真实性 / 检索充分性属"打开内部看"的二层指标，降为工程诊断层；另补用户真实诉求"表达合适性"与"拒答校准"。详见下方定稿版。

判定维度（定稿，两层）：

  • 用户价值层（黑盒，判分，进复合分）：
    • 正确完整性（answer_correct）：答案正确、覆盖金标准关键点，开放型按要点覆盖给部分分；含切题（相关性并入：答非所问即不正确）。
    • 表达合适性（format_appropriateness）：应答形态与问题类型匹配——问"是什么"给定义、问"区别"给对比、问"怎么开始"给路径、问"总结"给要点、问"出题"给题目；答对但形态错位（如问定义却给整章概述）= 扣分。
    • 拒答校准（refusal_calibration）：知识库与模型都不知道时明确说不知道；不编造事实 / 数字 / 来源；过度拒答是 UX 问题，拒答不足是安全问题（业界定义）。
  • 工程诊断层（白盒，不判分）：
    • 引用真实性（citation_truth，红线级）：引用的来源必须真实存在于知识库且内容吻合；伪造 / 张冠李戴 / 编造来源 = fail（must_pass 闸门，不进复合分）。对应 v1.0 引用真实性硬约束。
    • 检索充分性（retrieval_sufficiency，常驻诊断）：记录"是否检索到足以回答的内容"与"回答是否用上了检索内容"，失败归因（没检索到 vs 检索到没用上）。
    • faithfulness（按需审计）：回答论断与检索内容的吻合度；评测可信度审计——低 + 答案正确 = 用例被模型内化（评测污染），提示换题；不常驻打分。
