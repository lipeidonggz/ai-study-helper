调试记录：两个前端 bug（本次最有价值的收获）

Bug 1：SSE 解析器丢失事件名（前端不渲染的真正原因）

现象：后端流式响应正常（Network 面板能看到 delta 事件陆续到达），但界面完全无输出。

根因：client.ts 的解析器只读取 data: 行，把每个 SSE 块开头的 event: 行（事件名）丢弃。回调拿到的对象没有 event 字段，event.event === 'delta' 永远为 false，文本从未被拼进回复。

修复：每个块同时解析 event: 与 data: 并合并后再回调（onEvent({ event: eventName, ...data })）。用 Node 模拟后端真实字节流（含 JSON 从中间切开的网络分包）验证通过。

教训：SSE 协议的事件名在 event: 行，解析时必须成对消费，不能只取数据行。

Bug 2：Vue 3 响应式代理陷阱（修复 Bug 1 后暴露的第二层问题）

现象：把回复对象 push 进 ref 数组后，直接修改原始对象，模板不更新。

根因：messages.value.push(obj) 后数组里存的是 obj 的响应式代理；继续改原始对象不会触发渲染。

修复：push 后从数组取回代理再拼接：const reply = messages.value[messages.value.length - 1]。

教训：操作响应式数组中的元素，要从数组访问路径取回代理，不要持有原始对象引用。

附带排查：PowerShell 控制台“乱码”

Get-Content 显示中文为乱码是 PowerShell 用 GBK 解码 UTF-8 的显示问题，文件本身是合法 UTF-8（字节级校验确认），浏览器渲染正常，不影响运行。
