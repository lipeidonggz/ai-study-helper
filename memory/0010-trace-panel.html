会话元信息

日期：2026-08-03 参与：用户 + Codex（AI 协作开发助手） 类型：功能设计 / 实现

背景

用户读代码后反馈：看代码能理解处理流程，但对“stream 把 LLM 流式返回转成一个个 event”这类内部过程缺乏直观感受。为此新增功能：在前端界面上完整展示一次对话的内部处理过程。

功能定位：同时是调试工具、产品“说得清”（可解释性）的实现、阶段 4 可观测性的先导。

设计决策（已确认）

  • 两层展示：事件流层（每个 LLMEvent 原样展示）+ 语义层（轮次/工具调用/耗时统计）
  • 传输方式：扩展现有 SSE 协议，新增 trace 事件；现有 delta/error/done 不变，向后兼容
  • 后端实现：观察者模式 Trace 收集器——loop 只负责记录，chat.py 负责实时推送；为阶段 4 换持久化/对接观测平台预留
  • 默认状态：面板默认展开
  • v1 范围：只做实时展示，不做持久化与历史回看（阶段 4 再补）

实现内容

  • backend/app/agent/trace.py：Trace 记录器（step 序号、类型、数据、耗时）+ LLMEvent 转字典工具
  • backend/app/agent/loop.py：关键节点埋点——context（系统提示、消息数）/ round / llm_call（工具数、消息数）/ event（每个流式事件）/ tool_exec（名称、参数、结果、耗时）/ done（轮数、工具次数、结束原因）
  • backend/app/api/chat.py：Trace 实时转成 SSE trace 事件（用 deque 缓冲保证顺序：trace 先于对应文本发出）
  • frontend/src/App.vue + client.ts：“处理过程”面板——步骤时间线、类型徽章（工具调用/错误/结束高亮）、可展开 JSON 详情

验证

  • 后端 14 个测试全绿（新增 trace 步骤回归测试：context → round → llm_call → event → done）
  • 前端 vue-tsc 类型检查 + 构建通过
  • 待用户在界面实际验证：发一条消息，观察面板逐步出现各步骤

与路线图的关系

这是阶段 4“可观测性”的轻量先导：Trace 收集器接口已就位，后续持久化、指标面板、对接 Langfuse 等观测平台时只需扩展消费方，loop 不动。
