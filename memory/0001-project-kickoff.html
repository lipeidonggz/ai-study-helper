会话元信息

背景

用户在一个空目录（D:\lida-data\vscode\ai-study-helper）上发起新项目，目标是通过一步步构建和完善一个产品，练手自己学到的 AI Agent 设计开发知识。项目本身是学习载体，产品形态尚未确定。

讨论与决策

1. 项目核心目标

基于本目录一步步构建和完善一个产品，练手 AI Agent 设计开发相关的知识与技能；构建过程本身就是学习过程。

2. 过程记录规范：一律使用 HTML

用户明确要求所有过程记录（产品需求讨论、架构设计讨论、对比测试结果等）以 HTML 格式保存，而非 Markdown。决策内容：

  • 记录统一存放在 memory/ 目录，共享样式 memory/assets/style.css，每条记录为独立 HTML 文件，可离线直接打开阅读。
  • memory/index.html 作为记忆主页与索引，每次新增记录后同步更新。
  • 文件名规范：NNNN-短描述.html（NNNN 为会话序号）。
  • 触发机制：出现值得记录的内容时，Codex 主动提醒用户确认后记录；用户明确要求时直接记录。

3. 记忆体系设计（双轨）

经检查，~/.codex/memories_*.sqlite 是 Codex 系统自动管理的记忆管线（内部为 stage1/jobs 等系统表），不允许也不应由会话直接写入。因此采用：

  • 项目级持久记忆：根目录 AGENTS.md（Codex 每次会话自动读取，承载核心目标与铁律）+ memory/ HTML 记录库（承载完整过程记录）。
  • 系统级自动记忆：Codex 自动记忆机制随对话自行沉淀，无需手动维护。

4. 协作角色约定

Codex 在本项目中始终以客观、专业的伙伴身份参与讨论：对产品需求、架构设计、技术选型给出依据与取舍分析，不盲目迎合。

下一步

  1. 确定练手产品方向（候选方向与推荐见会话讨论）。
  2. 围绕选定方向进行第一轮产品需求讨论，产出需求文档并记录。
  3. 逐步进入架构设计与技术选型阶段。
