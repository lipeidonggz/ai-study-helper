目标定稿：RAG 增强的单轮对话

  • 定义：用户一个 query → Agent 一个完整回答。单轮 = 不依赖跨消息历史；Agent 内部手段不限（多次检索 / 工具调用均可），以"最优回答用户问题"为目标——内部手段本身是额外的探索验证空间；
  • 定目标视角：产品视角，不是技术实现视角——先定"产品要做到什么"，再倒推技术；
  • 多轮暂不上：RAG 难点先在单轮链路上做扎实；多轮是叠加层（单轮基础 + 上下文管理 / query 重写 / 何时检索），混在一起会让评测归因模糊。

现状核查（2026-09-01，用户质疑"多轮只是框架吧？"——属实）

  • 多轮会话 = 框架未接通：Port（SessionStore）+ 内存实现 + assemble 支持 history 参数都存在，但 chat API 不读历史、不存消息、run_agent_turn 不传 history（loop 注释："多轮记忆；当前调用方还没传"）；session_id 注释"当前还没真正持久化会话"——产品实际行为就是单轮，v1.0 定位单轮不是砍功能，是与现状一致；
  • kb_priority 模式 = 空壳提示词：context.py 身份句要求"优先使用个人知识库并给出引用来源"，但无任何检索能力（注释"阶段 2 后 RAG 优先"）——风险：提示词诱导模型编造"知识库来源"；v1.0 要把这段空头支票兑现成真检索。

讨论进展：问答类型分类的第一性是产品定位（2026-09-01）

为什么记这个：梳理"输出端问答类型"时反复觉得分类"不够第一性"——最后定位到根因：意图不是从问答技术、也不是从知识库主题推的，而是从产品定位推的（用户提出："用户的意图其实是跟产品定位相关的"）。

推导链（定稿）

产品定位（通用学习助手）→ 使用场景（学习）→ 用户意图（为什么来问）→ 应答形态（怎么帮学）→ 内容需求（需要什么知识）→ 承载形式（输入端）。定位是第一性的，知识库主题（三国 or 别的）只是载体，稍后再定。

分类方法论沉淀

  • 干净的分类三标准：单一轴（不能一会儿按答案形态、一会儿按难度、一会儿按边界切）、互斥且穷尽、同类共享同一答案结构；
  • 三个轴的关系：用户意图（为什么问，决定质量标准）→ 应答形态（给什么答案，决定实现）→ 问句形式（识别线索，不参与分类）；检索需求（单片段/多片段/聚合/多跳）与范围（内/外/模糊）是独立正交轴，不平铺进同一分类；
  • 从"三国问答"推的意图（快速查证/系统了解/比较决策/清单盘点/因果理解/来源核实）定位错位——那是"知识库问答工具"视角；学习助手视角下"快速查证（填空式）"不是主意图。

学习助手意图草案（7 类，待用户确认）

  1. 认知扩展：了解不了解的概念/人物/事件（"给我讲讲……"）——把不知道变成知道；
  2. 解惑：卡在一个点搞懂因果/机制（"为什么……"）——把不懂变成懂；
  3. 辨析：区分相近概念/人物/事件（"A 和 B 有什么区别"）——消除混淆；
  4. 溯源求证：回到原始材料看原文/出处（"原著怎么说""出自哪一回"）——证据意识；
  5. 结构化梳理：要一个主题的整体图景（时间线/清单/总览）——建立框架；
  6. 批判认知：区分演义与史实（三国场景下重要）——事实与虚构分离；
  7. 应用产出：把知识用于产出（写作业/做介绍），可能要引用格式。

对问题清单的影响：第 3 条（知识库外策略）受定位约束——学习助手定位下知识库外问题应"通用知识回答 + 标注非知识库来源"（呼应 boundary-scope-002 口径），而非纯拒答；纯拒答是"知识库问答工具"的定位。
