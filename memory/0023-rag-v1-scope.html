结论清单

  1. 目标定稿：RAG 增强的单轮对话——用户一个 query → Agent 一个完整回答；单轮 = 不依赖跨消息历史；Agent 内部手段不限（多次检索/工具调用均可），以"最优回答用户问题"为目标；产品视角定目标；多轮暂不上（多轮是单轮之上的叠加层）。
  2. 第一性方法论：问答类型分类的轴 = 产品定位（不是问答技术、不是知识库主题）。推导链：产品定位 → 使用场景 → 用户意图 → 应答形态 → 内容需求 → 承载形式。
  3. 输出端主线（学习过程）：初步学习（认知扩展 / 解惑 / 辨析）→ 内化学习（结构化梳理 / 溯源求证 / 批判认知）→ 产出辅助（应用产出）；补充环节：验证理解（含自测出题）、学习规划与延伸推荐、重点提炼 / 复习。
  4. v1.0 范围收敛："ok 状态" = 初步学习 + 内化核心环节（认知 / 解惑 / 辨析 / 梳理 / 溯源）达标；批判认知、应用产出部分覆盖；迁移应用（举一反三）明确缓做（单轮 + 跨域，后续版本方向）。
  5. 知识库外策略（受定位约束）：学习助手定位下 = 通用知识回答 + 标注"非知识库来源"（非纯拒答；纯拒答是"知识库问答工具"的定位）。
  6. 知识库主题（2026-09-01 定方向）：Agent 学习资料——入门教程 + 业界实践文章（Anthropic/OpenAI/国内厂商）+ 学术论文 + 项目自有文档（AGENTS.md + memory/ 关键笔记 + 后端架构文档，2026-09-01 确认）；知识深度覆盖入门 / 应用前沿 / 学术研究，支撑完整学习过程；混合策略：内容真实可学（不只要最新）+ 最新素材作为评测验证用例的极佳载体；
  7. 输入侧：需覆盖"向量化为主的输入知识处理主流策略"（长文本叙事 / 结构感知 / 结构化数据 / 短条目批量 / 多文档集合）；具体形态待输出端定稿后反推。
  8. 素材清单（2026-09-01 全部定稿，6 类）：教程 3 + 业界文章 16（A社 6 / OpenAI 3 / 个人站 7）+ The Batch 周刊 + 国内厂商文章 8 + 学术论文（arXiv 为主，半自动智能入库带 UI）+ 项目自有文档（AGENTS.md / memory 关键笔记 / backend 架构文档）；按模型熟悉度分级（高=评测污染重 / 低=评测干净），经典文承担认知与框架角色、用"模型已知 vs 检索溯源"对照用例把污染变成测试资产；逐条明细（含链接、熟悉度、载体）见第二部分「素材清单」。
  9. 版权合规口径（2026-09-01 补充）：素材许可矩阵确认——教程两件套 Apache-2.0（宽松）、Datawhale 版 CC BY-NC-SA（个人非商用可用）、厂商文章灰色（本地私有可用）、arXiv 入库记 license；素材只进本地、永不进仓库；公开/商用触发合规复审；仓库补 MIT LICENSE（出站方向）。详见第二部分「版权与许可」。

第二部分 · 现场细节（复原现场用）

讨论历程（决策链）

  1. 起点（目标定稿）：沛东提出 v1.0 = RAG 增强的单轮对话，暂不上多轮；确认定义：单 query → 完整回答，Agent 内部手段不限（额外的探索验证空间），产品视角定目标；
  2. 现状核查：多轮会话 = 框架未接通（Port + 内存实现 + assemble 支持 history，但 chat API 不传 history、session 不持久化，loop 注释"当前调用方还没传"）；kb_priority = 空壳提示词（要求"优先使用个人知识库并给出引用来源"但无检索能力——有诱导编造来源的风险）；
  3. 范围之争：练手应摸 RAG 生产主要问题（沛东要求：输入覆盖主流处理策略、输出覆盖主流问答类型）→ 三国单文本只覆盖"长文本 + 细节问答"，不够 → Codex 曾提议"多形态语料集合"（原著 + 结构化表 + 人物条目 + FAQ）；
  4. 分类方法论：输出端问答分类"不够第一性"（沛东直觉）→ Codex 拆解根因：之前分类混了三轴（答案形态 / 技术难度 / 产品边界）→ Codex 提出干净分类三标准（单一轴、互斥且穷尽、同类共享答案结构）→ 三轴递进关系：用户意图（决定质量标准）→ 应答形态（决定实现）→ 问句形式（识别线索）；检索需求与范围为独立正交轴；
  5. 定位第一性（沛东顿悟）："用户的意图其实是跟产品定位相关的"——意图分类从产品定位推，不从知识库主题推；三国版意图（快速查证等）是"知识库问答工具"视角，定位错位；
  6. 学习过程主线（沛东组织）：意图按"学习的典型过程"组织——初步学习（不知道→知道 / 不懂→懂 / 消除混淆）→ 内化学习（框架 / 证据 / 批判）→ 产出辅助；主线 = 对现实的建模（沛东观点，Codex 确认：有损压缩——能"主"、覆盖绝大多数环节、给功能取舍依据即可；不追求穷尽，靠验证暴露后迭代补——与 0022"评测体系就绪不追求完美"同原则）；
  7. 环节扫描（Codex 补漏）：补"验证理解"（含自测出题）；补"学习规划与延伸推荐"（入口：'我想学三国从哪开始'）；补"重点提炼 / 复习"（巩固：'帮我总结要点'，Bloom 认知目标里"记忆"这条腿此前是空的）；"迁移应用 / 举一反三"明确缓做。
  8. 知识库主题变更：三国 → Agent 学习资料（2026-09-01）：沛东提出——定位是学习助手、在学 Agent，输入资料就用 Agent 学习资料（业界文章 / 论文 / 教程），知识深度覆盖入门-应用前沿-学术研究，支撑完整学习过程。Codex 确认方向对（知识库与学习目标强一致、深度分层映射主线各环节、多形态贴输入覆盖目标），但指出漏洞：换掉三国并不能解决评测污染——Agent 资料模型同样熟甚至更熟；对抗手段四条：①内容时效性（2025-2026 新实践）②自有内容（项目文档进知识库，模型绝对没见过，评测最干净）③引用约束（必须引用原文片段）④细节用例（问原文具体表述/数据/出处逼检索）。沛东拍板：混合策略"都要"——知识库要真实可学（自己就是用户），最新素材纳入作评测验证载体；自有内容"妙不可言"；引用约束确认；细节用例待定内容范围后按用户环节构造；实操晚点谈，先用产品经理视角（做时发现问题再讨价还价优先级）。
  9. 素材清单定稿（2026-09-01 续）：沛东确认教程两件套（李博杰书 + HF 课程）后要求扩展文章：A社不能只有《Building Effective Agents》，要 OpenAI 与个人站（Agent 业界有名）。Codex 检索验证后给出三组候选，核心标准 = 时效性（2025-2026 新文模型不熟，评测干净）：A社 5 篇核心 + 可选 Claude Code Best Practices；OpenAI 3 篇（含意外收获 Harness Engineering 2026-02，与项目 AGENTS.md / 记忆体系强相关）；个人站 5 篇 + 可选 Hamel evals 系列；Lilian 2026-07 Harness 长文与 OpenAI / A社 harness 文构成三方对照，天然是"辨析 / 批判"素材。沛东：可选的全收了。素材越挖越多，知识库还没开建，清单已近 20 条。
  10. 吴恩达教程发现（2026-09-01）：沛东问吴恩达是否有文字版教程（视频版暂不管）。Codex 查证：官方 Agentic AI 系列（2025-09/10，DeepLearning.AI）以视频为主（31 视频课 + 3 阅读课），逐字稿不便抓取；但 Datawhale 有完整中文翻译整理版（5 模块 Markdown 全部完成），与李博杰书同一条 Markdown 采集管线，收；《Machine Learning Yearning》（2018 PDF）纯文字但老且非 Agent 主题，未选；The Batch 周刊纯文字、持续更新、模型不熟（如 2025-10《Disciplined Evals and Error Analysis Accelerate Agentic AI》与评测工作直接共鸣），沛东确认收入。
  11. 国内厂商文章升格（2026-09-01，沛东洞察）：沛东指出前沿文章（A社 / OpenAI / 个人站）大多以 CodeAgent 为分析对象，而编码域基础设施明显好于其他领域，知识库因此自带偏见；国内厂商文章可补此偏见。Codex 认同并挖根因：编码域自带验证闭环（编译 / 测试 / lint / CI 确定性反馈），非编码域反馈模糊、评测要自己造——正对应 0022 手搓评测可信度的经历，本项目本身就是"难域"；前沿语料是"方便域采样偏差"。国内厂商文章另补"约束对标"：国产模型 / 成本敏感 / 中文环境 / 合规要求下硬扛工程，与 DeepSeek 栈处境更贴近。同时泼冷水：非所有国内厂商文章都补偏见，多为发布通稿 / 译文，需按 4 条选材标准人工筛。
  12. 学术论文来源与入库方式（2026-09-01）：沛东问期刊/会议论文是否不易公开检索，忆起"某 A 打头网站"（arXiv）；Codex 确认三类公开性：纯期刊有付费墙/延迟开放、AI 顶会（NeurIPS/ICML/ICLR 走 OpenReview、ACL 系列走 ACL Anthology）反而公开、arXiv 是公共预印本层。沛东进一步提出产品定位问题：是否做"自动智能入库"？判断学术论文是最合适对象（来源稳定/格式稳定/结构化最好）。Codex 认同论文最适合，但指出盲点：论文只是五类素材之一且是最容易的一类，全类型自动入库难度高且在主线上价值低；且全自动违背"基础件人工复核"原则。沛东拍板：其他类型全自动暂不做；论文类做半自动智能入库，且要 UI 不要脚本（脚本太难用）。
  13. 论文入库 UI 边界确认 + 项目自有文档范围确认（2026-09-01）：Codex 给出 UI 四步流程（检索条件 → AI 打分排序候选清单 → 人工勾选 → 入库结果），并说明筛选规则独立成可配置文本是论文"范围"的落点；沛东确认理解正确。项目自有文档范围草案（AGENTS.md + memory/ 关键笔记 + backend 架构文档），沛东确认。素材清单至此全部定稿。
  14. 版权合规（2026-09-01，沛东发问）：沛东问"教程拿过来进知识库，会不会涉及版权？"。Codex 查证给出许可矩阵：李博杰书 / HF Course 为 Apache-2.0（宽松）；Datawhale 版吴恩达为 CC BY-NC-SA 4.0（非商业 + 相同方式共享）；A社 / OpenAI / 国内厂商 / The Batch 版权归厂商属灰色；arXiv 需逐篇记录 license 字段。沛东补充两个关键事实：项目代码公开在 GitHub、暂无商用计划。Codex 据此收敛：真正的风险不是"商用"而是"公开分发"——仓库数据文件已在 .gitignore，素材只进本地永不进仓库，风险从"公开再分发"降级为"个人学习使用"；NC 条款因不商用而满足；SA 条款只在"改编+再分发"时触发，本地入库不触发。决策：素材清单补"许可/风险"口径 + 采集时逐条记录 manifest + 本地私有 + 公开/商用触发合规复审（换 Datawhale 版、厂商全文转索引+摘要+引用）；仓库补 LICENSE（MIT，2026-09-01，出站方向）。
