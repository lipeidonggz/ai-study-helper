· 附带回答了一个疑问：中文"威胁"落地时会落到 threat model(0.839)——抽取抽的是"威胁"，落地才可能碰巧落到 `threat model`，而后者语义上并不精确（威胁 ≠ 威胁模型）。这说明抽取与落地必须分开看。

⑤ 四条结构性问题（从这 20 条里归纳出来的）

一、"概念锚只支持术语原样"这条假设，把主力悄悄挪到了 statement 向量。实测：cost、role、harness 都不在概念表（blocks / observe 是谓词不是概念）。凡是用自然语言描述概念的（成本 / 开销、人的角色、最后一道防线），精确锚就落空。所以这套方案的真实形态是：statement 向量是主力，精确锚是收窄项——这决定了投入顺序：statement 向量库是必需品，不是可选优化。
二、入口清单漏了"谓词"——已解决（2026-09-21 确认加入）。2、8、10、14 本质都是谓词过滤（costs 7 / blocks 9 / protects_against 9 / detects 8 / monitors 2 / affects 3），而谓词是 38 条受控表、精确可查、零成本，且不随语料增长。
为什么它比概念好做：概念表会随语料线性涨（一篇 A5 就有 399 个），而谓词永远只有 38 条——所以"中文触发词 → 谓词"的映射可以人工维护、成本极低，而概念锚没有这个便利（概念锚只能靠检索 + 术语原样）。
它解决的那个具体问题：用户说"成本"时，库里没有概念 cost，但有谓词 costs。
三、"链"和"矛盾"这套流程给不出，而矛盾那条不是可以后置的。这套流程的产出是扁平的一组 statement + 它们的 chunk。11–13 要路径、16/18/19 要"把同一主题下的多条断言并置比较"——后者在这套流程里完全没有对应步骤（多跳可以后置，但"同主题聚类 + 比较"连提都没提）。它们现在只能靠"把材料丢给 LLM 自己看"，效果取决于召回是否恰好把两边都召回来。
四、谓词族 ≠ 内容类别——两者正交，所以"用谓词划族"只是近似（2026-09-21 第 3 条实测得出）。"防护手段"是一个内容类别，而谓词是关系类型；一条断言算不算"防护手段"取决于它讲什么内容，与它用哪个谓词（constrains / isolates / blocks / enforces / uses）没有必然关系。
于是必然两头出问题：划窄了漏（第 3 条实测漏召回 62 条，含标准答案级的 Anthropic --constrains--> agent action constraints）、划宽了把不是手段的拉进来（detects 里混着基准测试、monitors 里混着"人监督 agent"）。
含义："一类东西有哪些"这类问题，图里现在没有"内容类别"这个维度——概念表 399 个全是 type=concept，既无类型也无上位节点。三条候选路径：① 概念的类别 / 上位节点（最正，但图里没有原料，属编译层的活）；② 概念概括名 + top-k 族锚（实测同族碎片在向量空间聚团，可能可用，待标定）；③ 接受"部分 + 声明"（谓词族给材料、LLM 筛、如实声明不完整）。
附注 · 细化版第 3 条（"Agent 安全防护手段都有哪些，各自针对什么威胁"）带出两条（2026-09-21 实测）——把范围词 agent 补进来之后，问题骨架没变（仍是"内容类别枚举 + 关系"），但暴露两件事：
① 范围词不能当 AND 过滤键，它在两端表现相反。chunk 层 24 块里 17 块都出现 agent（A5 全篇都在讲 agent，近乎零区分度）；statement 端点层却把谓词族 39 条砍到 5 条 / 5 块——因为端点多写具体名字（sandbox / egress controls / VM / Claude Code / sub-agents），很少直接写 agent。换一条路也不行："端点含 agent"（不限谓词）48 条 / 14 块里混着大量无关（agent --acts_on--> files / sockets / processes、agent --is--> user extension）。所以范围词的正当用法是软加权 / 只在覆盖声明里体现，不是过滤键——与 2026-09-19"枚举型问题再 AND 概念约束，命中 113 条 → 4 条"是同一个病。
② "Agent 安全防护"自带方向歧义，图里没有这个维度。防 Agent 作恶（containment，A5 主线；正文明说 We're not protecting user machines from agents; we're protecting our own infrastructure）与防 Agent 被攻击（MCP servers --provides--> untrusted content in agent context、three components --protects_against--> external content the agent can reach）是两类内容；"都有哪些"要求两面都列，而谓词族与概念锚都不编码这个方向，只能靠 LLM 在线分。

⑥ 一个必须先定死的技术点：statement 的向量用什么文本？

若只用 subject + predicate + object（三个短词）——召回不到细节（"17%"、"同意之前"这类），而且实测过短文本的相似度分数不可分（噪声地板 0.839 > 信号 0.830）。
所以必须把逐字证据句 evidence_texts 一起编码；这样一来 statement 向量其实≈"聚焦版的 chunk 向量"。
同时要看清一个 trade-off：换成 statement 向量会把"检索覆盖"绑定到"抽取覆盖"——图只含被抽成断言的内容，而 chunk 是全量的。更稳的是两者都留：statement 向量用于精确定位断言，chunk 向量兜住没被抽成断言的内容。
