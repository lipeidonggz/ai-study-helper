# 0026-3 覆盖判官的诱饵假阳性：排除句当锚、论证式陷阱与 2×2 拆变量

> 系列：RAG 评测工程（0026 实践复盘）· 状态：初稿，待作者审校
> 对应原始记录：memory/0026 阶段 C7（2026-09-07）
> 摘要：判官假阳性居高不下？三个反转在坑你：排除句的词成了"锚"；让它写论证它反而会编理由；不拆变量就会把假象当真。2×2 实验拆出真相。

## 30 秒判断

如果你的 LLM 判官出现"同一条输出反复横跳、假阳性居高不下"，而且你已经试过加约束、换输出结构、甚至让判官写完整论证，请先读这篇：我们踩过的三个坑可能正是你现在踩的——

1. **排除句被当锚**：探针里写"……不算覆盖"，判官反而把"不算"里点名的内容当成命中证据；
2. **论证式陷阱**：让判官"因为……所以……"地论证，短期压住假阳性，换条输出就翻车——它会编一个像样的理由；
3. **混变量假象**：不做变量拆分，你会把"论证式有效"这种错误结论当真，白白加复杂度。

正确的修法不是给判官加压，而是**区分探针的正面要件与排除句，并做 2×2 变量拆分找到真正有效的成分**。

## 1. 起题：同输入重判翻得"有点厉害"

某次跑批后，我们对一条 Agent 输出（UI#6）做同输入重判 5 次，o2-e2 / o2-e3 两个覆盖点各出现 2 covered / 3 not_covered——"翻得有点厉害"。此前刚从这个 attempt 得出"a5-e2 是 Agent 输出波动"的结论，现在同一条输入却是判官自己不稳定，坑又深了一层。

把问题拆开，根因其实有两层：

**真值层**：这条输出的注入块里根本没有 O2 文章的"工程师角色重定义"（o2-e2 素材）和"吞吐改变合并哲学"（o2-e3 素材）——内容本来就不在，真值应该判 not_covered。

**判官层**：判官提示词里有句引导"标 covered 必须在 evidence 中引用与探针要素对应的输出原句"。问题在于探针里有排除句（"……不算覆盖"），引导句把**排除句里点名的词也变成了可锚定要素**。于是判官把"0 行手写 + 1/10 人力时间"（对应排除句"仅报告产出成效不算"）和"开 PR 自动合并"（对应排除句"仅单一自动化动作不算"）当成了覆盖证据。

基线 ×20 的假阳性率：o2-e2 16/20、o2-e3 15/20。判官不是偶尔走神，是稳定地被诱饵勾走。

## 2. 第一直觉失败：让判官"论证"

面对"evidence 与结论脱节"，第一反应是让判官把 evidence 升级成完整论证——"因为输出里有 X，所以该点 covered"。实验（80 次）：

- UI#6 假阳性 80% → 0/20，看似有效；
- 换到 UI#7 却 14/20 依旧；
- 更糟的是，论证样本暴露了判官在**编造引文**：输出里根本没有"评审交由 agent 之间完成"，判官却写进论证；还把后台 GC / doc-gardening 开 PR 的执行细节硬扯成"职责变化"。

结论：论证结构把"不写理由直接标 covered"治住了，却挡不住"编一个像样理由标 covered"——**自圆其说坑**。模型越长篇大论越会自我圆场，论证不是解药，是放大器。

> 术语锚 · evidence-first：我们最终采用的结构是"先写依据（摘抄输出原句），后给判定"。关键是依据必须是**摘抄/提取**动作，不能是"定位/检索"或"推理/论证"——摘抄不会编，论证会编。这与引用判官（依据=在几十个相似块里定位）是两种不同的 reason-first，后者会翻车。

## 3. 变量拆分：2×2 找到真正有效的成分

如果只做"论证式 vs 现版"的对照，你会得出"论证式治好了 UI#6"的结论——就像我们差点做的那样。但问题是：论证式实验里**同时**加了别的东西吗？没有，但"UI#6 好转"可能来自换样本的运气，也可能来自别的隐性变量。

我们把两个变量显式拆开：

- 结构：现版 evidence-only（摘抄） vs 论证式（因为…所以…）；
- 口径：是否加硬条款"探针排除内容不得作为 covered 依据"。

四条件 ×20（160 次）：

| 条件 | 结构 | 口径条款 | UI#6 | UI#7 |
|---|---|---|---|---|
| A | evidence-only | 无 | e2 12C/8N | 4C/16N |
| B | evidence-only | 有 | 双 0/20 | 双 0/20 |
| C | 论证式 | 无 | 0/20 | 13C/7N |
| D | 论证式 | 有 | 0/20 | 10C/10N |

结论：**真正管用的是口径条款**（"排除内容不得作为 covered 依据"），论证式单独用在难诱饵上反而比现版更糟。早前"论证式治好了 UI#6"是混变量得出的假象——C 在 UI#6 也 0/20，但 UI#7 打回原形。

## 4. 防过头：硬条款会不会误伤真覆盖？

新口径"排除句内容不得作为依据"有个天然风险：如果输出真的覆盖了正面要件、只是顺带提到排除句里的词，会不会被误杀？

合成正例验证（职责细节齐全 + 顺带提"1/10 时间 / 不手写代码"）×20：三个条件全部 20/20 covered，未误伤。

o2-c1 真覆盖验证（外层命题 + 三要素概括）×20：rootfix / pureB / hybrid_noex 三个变体全部 20/20——证明"概括口号不算"不会误伤"以概括为正面"的点。

到这里，规则形态基本清楚了，但还有一个承重墙问题。

## 5. 例子是承重墙：别从共享提示词里删掉，迁进探针

实验里有个变体 hybrid_noex——去掉口径条款里的具体例子（比如"仅报告产出成效（代码量、耗时）不算"这种）。结果在 UI#6 负例上 4C/6N，40% 假阳性回来了。

也就是说：**条款里的具体例子是承重墙，不能删**。但例子又不能留在共享提示词里——共享提示词是全局的，写用例例子等于用例污染（把某个用例的具体内容泄漏进所有判官调用）。

解法：把例子从共享提示词迁到**用例侧探针**，即每个点的排除句本身就用例子化的语言写清楚"什么不算"：

- o2-e2 探针："仅陈述'人不再写代码/设计环境'类概括，或仅报告产出成效（代码量、耗时），不算覆盖"；
- o2-e3 探针："仅描述单一自动化动作（如某类 PR 自动合并）而未建立'吞吐 → 规则变化'的论述，不算覆盖"。

最终形态：系统覆盖模块保留五条通用规则（打标范围 / evidence 自洽 / 从严+等价描述 / 易混主题分开 / equivocal），用户消息只剩一条口径（正面要件 vs 排除句），**共享提示词层零重复、零例子**；具体反例以排除句形态生活在各自的探针里。

全量回归 Run#130（去双写去例子）与 Run#131（再清历史重复）均无退化：7 个 core + o2-e1 稳定 20/20 covered，扩展组稳定缺失，偶发假阳性 1–2/20 留在噪声带。

## 6. 收口：三方归因，判官只是其中一方

同一批真实跑批（Run#128–131）在判官修稳后，可以干净地分成三类：

- Agent 生成侧波动（同注入、输出时有时无）；
- 检索不充分（目标章节没注入，稳定 20/20 缺失）；
- 判官残余假阳性（1–2/20，噪声带，交 repeat 统计吸收）。

判官校准的价值在这里兑现：**判官稳定后，跨 attempt 的差异才能归因到输出本身**。如果你在判官还没稳的时候统计"为什么红"，三分之一的红其实是尺子在抖。

## 7. 可带走的清单

1. 探针里的排除句会变成诱饵：covered 必须引用**正面要件**对应原句；排除句只在"论述退化为排除形态"时触发，不因字眼出现而否决；
2. 论证式 evidence 会诱发编造：证据必须是摘抄/提取，不是推理/论证；
3. 实验必须拆变量：任何"新方案有效"的结论，先问它是否混了别的变量（2×2 是底线）；
4. 共享提示词不写用例例子，反例例子化后放进用例探针；
5. 规则只保留一处（去双写）：同一口径写两遍，改一处漏一处，判官就会行为漂移；
6. 修判官之前先查上游：同输入不稳 → 变量分离 → 看 evidence 聚类 → 回原文核探针 → 改金标准，而不是压判官。

## 8. 边界声明

- 单一判官模型、温度 0、覆盖性标注这一类任务；换任务类型（如引用核对）结论需重验——引用侧甚至出现相反的 reason-first 翻车。
- "1–2/20 交 repeat 吸收"是噪声容忍线，不是通用阈值，需按项目对误报的容忍度重标。
- 本文处理的是"该有的都有"（覆盖性）判官；"不该有的没有"（排除性/错误内容检测）是更难的另一类问题，不在本文范围。
