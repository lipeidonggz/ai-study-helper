# 0026-1 引用真实性的两阶段工程化：声明组与确定性提取

> 系列：RAG 评测工程（0026 实践复盘）· 状态：初稿，待作者审校
> 对应原始记录：memory/0026 阶段 C4/C5（2026-09-05 晚 ~ 09-06）
> 摘要：给 RAG 做引用审计，最贵的不是判官，是让它拆声明——它两次系统性翻车。把提取交给纯规则，判定单元从"对子"改"声明组"，误杀清零。

## 30 秒判断

如果你在做 RAG / Agent 的引用审计（citation truthfulness），并且正被三件事折磨——"点名整篇文章的声明被逐块判死""同一组引用内部自相矛盾""让 LLM 拆声明时它总在编"——这篇文章给出一条完整的分工方案：

**把"提取待核对的声明"从 LLM 手里拿掉，交给纯规则；LLM 只保留一件事：核对"一组引用块的并集是否真的支撑整条声明"。** 中间的判定单元从"（声明，单块）对子"改成"（声明，引用组）"，配合从紧口径、缺席规则和组隔离，能把引用审计从"机制误杀 + 执行漂移"调到稳定可复现。

适合谁读：正在给 RAG 系统做引用真实性评测、或想给生成结果加 grounding 审计的工程师。不需要完整背景，但最好写过至少一个 judge prompt。

## 1. 问题：判官在判什么，为什么会判错

先说清楚我们审计的对象。学习助手的答案里会出现两类引用承诺：

- 显式编号引用：`……[4]`；
- 点名整篇文档：`OpenAI《Harness engineering》一文认为……`。

红线口径是 precision-only：**只对"答案实际给出的引用承诺"负责**——来源真实、归属正确、内容吻合；不追究"所有该标的都标了"（那是 recall 侧，交给抽样审计）。这条口径本身是另一篇文章的素材，这里只需要知道：红线判的是"给出即负责"。

判官的输入是"模型输出 + 注入的证据块"，输出是每条声明的支撑结论。我们最初的实现长这样：

1. 阶段一（LLM）：把回答拆成原子声明，标注 cited / retrieval / internal，并给声明配上引用；
2. 阶段二（LLM）：逐对核对——每对（声明，引用块）判内容是否吻合。

听起来顺理成章，实测全崩。崩的方式很有信息量。

## 2. 第一类翻车：核对单元与声明的语义粒度错配

重判一批真实输出（Run#126），六条 fail 逐条归类，出现两个机制性误杀：

**Type A：点名整篇的声明被逐块判死。** 模型写"OpenAI《Harness engineering》的核心主张是……"，这条声明锚定的是整篇文章，但阶段二把它拆成 7 对，逐块问"这一块是否完整支撑整句"——单块当然撑不起整篇主张，于是 6 对 violation。判官在惩罚一个不存在的要求。

**Type B：多编号组内要求逐块全覆盖。** 扫描全量 167 组多编号声明，14 组出现"同组既有 ok 又有 violation"的自相矛盾。最典型的一条：判官自己的 reason 写着"该表述在块 6 中"，却仍把块 9 判了 violation。多块引用（`[2][5]`）合起来支撑一句时，任何"每块都必须独立扛起整句"的隐含要求都会制造误杀。

这不是提示词能修好的抖动，是**判定单元选错了**：一条声明的语义范围是"整篇文档"或"一组块的并集"，你却拿"单个块"去套。

> 术语锚 · 声明组：配对从"（声明，引用块）对子"升级为"（声明，引用组）"——编号引用组 = 所引的若干块；点名整篇 = 该源全部注入块。阶段二只判"组内块并集是否支撑整条声明"，聚合也按声明级，不再"任一对子 violation → fail"。

同行证据也指向同一结论：JHU 的论文《Are Finer Citations Always Better?》（arXiv 2604.01432）实测强制句子级细粒度引用会把归因质量拉低 16–276%——粒度必须对齐声明的语义范围，不是越细越好。

## 3. 第二类翻车：让 LLM 拆声明，它两次系统性翻车

把判定单元改成声明组后重判，大部分 Type A/B 消失，但又冒出两处新残留，根因都指向**阶段一不可靠**：

- `#13`：模型输出里有一句无编号的综论"Anthropic 解决的是……"，LLM 拆声明时自作主张给它配了 `refs=O2`——与声明文本点名的来源自相矛盾。同输出 ×20 里 17 次配错源，85% 系统性错源，不是偶发。
- `#4`：表格跨格坍缩——原输出里 `[9][11]` 标在 OpenAI 那一列，LLM 提取器却拼出"Anthropic 文 [9][11]……"这种句子，旧判里以为是真归属错误（Type C），查证后是提取伪影。

作者当时的直觉很直接："从模型输出里提取待检查的声明和引用块，不需要走 LLM 吧？规则好像十分清晰。"复盘下来这个直觉是对的，但要拆三层看：

1. 找 `[n]`、做配对，**本来就不该走 LLM**——确定性任务，冤枉它；
2. "切出可独立核对的声明"卡在**引用作用域约定**（句尾/格尾引用覆盖到哪、句中多标引怎么归属）——这是约定问题，不是能力问题，LLM 在凭感觉替我们定约定，而且不稳定；
3. "哪些算引用承诺 / 元陈述"大部分规则清楚，只剩少量语义边界。

于是阶段一整体改成确定性提取，LLM 调用直接删除。

## 4. 确定性提取器长什么样

核心规则（全部无 LLM）：

- **单元切分**：散文按句末标点拆（引号内不拆，否则 `。"` 后的 `[n]` 会被甩成空壳声明）；Markdown 表格按行按格拆，每格一个单元；
- **标引组**：连续 `[n]`（中间只有空白/纯标点）合并成一组；范围引用 `[1-5]` 不算标引；
- **分段规则**：句中的引用组只锚"上一组边界 → 它自己"；句尾/格尾的组锚"上一组边界 → 单元结尾"（含尾段）；
- **元陈述规则表**：命中"资料不全 / 摘录片段 / 未呈现全文 / 我将 / 综上"等即整单元跳过，宁漏勿杀（漏 = recall 侧，安全方向）；
- **标题点名归因**：无 `[n]` 但命中唯一标题别名 + 单元含归因谓词/冒号，才产源级声明；
- **红线范围收紧**：只查"带 `[n]` 的单元 + 带完整标题点名归因的单元"；品牌泛称、无编号综论句不进红线。

为什么要"宁可漏"？因为漏掉的声明落在 recall 侧（本来就是抽样审计的地盘），而误杀会直接制造假 fail。宁可少查，不可错杀。

顺带解释两个当时纠缠很久的词：

- **格尾**：表格单元格的末尾。作者行"Ryan Lopopolo……致谢 Victor/Zach [7]"就是整格 `[7]` 覆盖整格内容、作者名却没标到 byline 块 `[10]` 的典型案例；
- **及时标引**：隐含前提是模型应该就近标引。长句/长格末尾集中堆 `[n]` 是反模式——它会让整段变成一个声明，然后被并集核对，等于把"标引纪律"问题转嫁给判官。

## 5. 从紧口径与缺席规则：判官该有的两副铁面

确定性提取解决了"谁来拆"，剩下的"怎么判"还要定两个口径：

**从紧口径（整句/整格判）**：标引覆盖所在单元的全部事实成分，欠标即 fail。为什么不能宽松？因为"就近引用"无法定义——一句话中间没标、句尾标了一个 `[n]`，你说它覆盖前半句还是只覆盖尾半句？没有确定性的单元边界，一切"宽松"都是判官自由心证。两阶段存在的理由就在这里：**阶段一用规则定死边界，阶段二才谈得上判覆盖**。

**缺席规则**：对"未署名 / 无日期 / 未提及 / 不含 X"这类缺席性断言，**禁止缺席推理**——块里没写 ≠ 能证明缺席。判官必须找到组内某块原文直接陈述该缺失，才算有据。`#16` 的 gid1/gid2 就是反面教材：模型断言"作者未署名 [1]"，判官却替它圆场放行；从紧后稳定 fail。

这两条都指向同一个原则：**判官可以严，但不能脑补。**

## 6. 组隔离：稳定性的机制关键

把口径收紧后，判官本身又开始翻：`#13` 6/20 翻转——它对"整句成分须组内有据"的执行时严时宽。观察证据泄露了机制：整批 30–70 组一次调用，判官会**跨组偷块**——拿别的组的块给当前组"圆"支撑。典型样本：`#16` gid0 曾把块 `[10]` 的 byline 安到块 `[7]` 上；`#13` gid20 用组外的 `[2][3]` 放行。

修法很朴素：**降批 + 只准引用本组块**。从 batch 6 降到 batch 3：

| 组 | 现象 | batch 6 | batch 3 |
|---|---|---|---|
| gid20 | Anthropic 半句未标（refs=[9]） | 2/20 翻 | fail 18/20 |
| gid24 | "用户机器"成分在 [4]，[5] 明说 claude.ai 不护用户机器 | 同左 | fail 19/20 |
| gid25 | "风格失守"边缘 | 噪声 | fail 5/20 |

整 run fail 20/20，但逐句分布揭示真相：34 句里 31 句稳定 pass，只有两句稳定欠标 + 一句边缘噪声。**run 级通过率被单条稳定 fail 决定，量化欠标普遍性必须看逐句分布**——17/20 fail 不等于 85% 欠标，这是 0026 里反复出现的统计教训。

> 术语锚 · 组隔离：阶段二每次调用只传一组（或小批）声明及其组内块，并明令"只准引用本组块"。判断瓶颈往往不在推理深度，在证据隔离——把正确的块放到眼前，比让模型在 70 组里大海捞针可靠得多。

## 7. 收口：稳定 fail 集是 Agent 的欠标清单

全部落地后（确定性提取 + 声明组 + 从紧 + 缺席 + 组隔离），重判结果：

- 旧 6 条 fail（#4/#5/#6/#13/#18/#19）全是提取/粒度伪影 → 20/20 pass；
- #13/#18 同输出 ×20 稳定 pass；
- #16 从严后 20/20 fail（作者行欠标 + 缺席断言瞎挂）；
- #12 稳定 fail 三条，逐条人工确认判官没错：口号句真误引、OpenAI 前提缺前半标引、跨源概念嫁接。

到这里，引用判官侧的稳定 fail 集就构成了一份**Agent 欠标清单**——每一条都能指回模型的具体行为（该标尽标、就近标引、别拿 A 的块撑 B 的话）。判官校准的价值在此兑现：判官稳定后，跨 attempt 的差异才能干净归因到输出本身，而不是判官噪声。

## 8. 可带走的清单

1. **判定单元对齐声明语义范围**：点名整篇 → 整源组；多编号 → 编号组并集；别拿单块套整句。
2. **能确定性的就确定性**：`[n]` 提取、单元切分、配对是纯规则活，交给 LLM 只会引入不稳定。
3. **宁漏勿杀**：元陈述跳过规则宁可漏（recall 侧安全），不可误杀（制造假 fail）。
4. **从紧口径是两阶段的前提**：单元边界必须由规则定死，"就近"在自由裁量里无法定义。
5. **禁止缺席推理**：块沉默 ≠ 缺席证明，判官不许替模型脑补。
6. **组隔离优先于推理增强**：跨组偷块是稳定性的头号杀手，降批 + 限定引用范围比加 prompt 管用。
7. **看逐句分布，不看 run 级通过率**：单条稳定 fail 会决定整个 run 的红，别拿 run 级数字推断欠标普遍性。

## 9. 边界声明

- 单一判官模型、温度 0、单一项目（RAG 学习助手）、一组对比型任务族；换模型/领域需重验，但"确定性提取 + 语义核对"的分工原则我们认为跨场景成立。
- 元陈述规则表随语料类型扩展（引用说明、资料局限、摘录声明等），覆盖不全时宁漏勿杀，会有 recall 侧漏查，靠抽样审计兜底。
- 本文只谈"标得对不对"（precision 红线）；"该标的都标了"（recall）是另一套问题，需要 necessity 判定，不是本文范围。
