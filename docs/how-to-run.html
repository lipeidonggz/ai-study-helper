运行指南

ai-study-helper · 阶段 1 骨架（前后端分离：FastAPI + Vue 3）

前提

  • Python 3.14（后端依赖已安装到 backend\.venv）
  • Node 24 / npm（前端依赖已安装到 frontend\node_modules）
  • 调用真实模型需要先在页面右上角“设置”里配置 DeepSeek API Key；评测台支持 Fake 干跑（不联网、不花钱）验证管道。

启动步骤（两个终端）

1. 启动后端（端口 8000）

cd D:\lida-data\vscode\ai-study-helper\backend
.\venv\Scripts\python.exe -m uvicorn app.main:app --port 8000 --reload --no-use-colors

看到 Uvicorn running on http://127.0.0.1:8000 即成功。--reload 会在修改代码后自动重启（开发用），--no-use-colors 关闭彩色日志（防止终端不支持 ANSI 时显示转义码乱码）。

注意：请在 backend 目录下运行，不要进到 .venv\Scripts 里再执行——否则 --reload 会监听错误目录（.venv\Scripts），代码改动不会触发重启。

2. 启动前端（端口 5173）

cd D:\lida-data\vscode\ai-study-helper\frontend
npm run dev

看到 Local: http://localhost:5173/ 即成功。开发环境下 /api 请求由 Vite 自动代理到后端 8000。

验证

  1. 浏览器打开 http://localhost:5173/，应显示“AI 助手”对话界面，可切换三种会话模式（通用 / 知识库优先 / 工具增强）。
  2. 配置 Key 后输入任意消息发送，应流式返回真实回答；未配置时会提示先到“设置”里配置。
  3. 直接访问 http://127.0.0.1:8000/health，应返回 {"status":"ok","app":"ai-study-helper"}，说明后端存活（注意健康检查挂在 /health，不在 /api 下）。
  4. 评测台：聊天页顶部点击“评测台”（新标签页打开），在“测试管理”里可新建跑批（Fake 干跑 / 真实模型），跑批进度自动刷新。

常见问题

  • 端口被占用（后端 address already in use，或前端 Port 5173 is already in use）：
    Get-NetTCPConnection -State Listen -LocalPort 8000,5173 | Select LocalPort, OwningProcess
    然后结束对应进程：taskkill /PID <进程号> /T /F（确认进程是自己项目残留的再杀）。
  • 日志出现 [32mINFO[0m 之类的“乱码”：那不是乱码，是 ANSI 颜色控制码未被终端解析。解决：启动参数加 --no-use-colors；如果终端支持 ANSI（如 Windows Terminal / PowerShell 7）则无需处理。
  • 日志/输出中文乱码：启动前执行 [Console]::OutputEncoding = [System.Text.Encoding]::UTF8，必要时加 $env:PYTHONIOENCODING='utf-8'。
  • PowerShell 里发中文请求乱码：是终端编码问题，浏览器界面不受影响；命令行测试建议用英文消息或先执行 [Console]::OutputEncoding=[Text.Encoding]::UTF8。
  • 改了后端代码没生效：确认启动时带了 --reload；没带则手动重启。
  • 前端改了没反应：Vite 默认热更新，确认启动的是 npm run dev 而非 build 产物。
  • 评测跑批（真实模型）全部报 All connection attempts failed：后端进程没有出网权限（常见于后端由 Codex 沙箱启动，沙箱限制网络）。解决：在沙箱外启动后端（直接开终端跑 uvicorn，或让 Codex 提权启动），再重新跑批。
